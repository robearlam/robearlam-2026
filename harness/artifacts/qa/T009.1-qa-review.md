## Issues Identified

### Issue 1 — `aria-live` placement deviates from blog reference pattern

**Description:** In `BlogFeedClient`, `aria-live="polite"` is placed on the outer `<section>` element, which encompasses the loading indicator, error, and end-of-list message alongside the post list. In `VideosGridClient`, `aria-live="polite"` is placed on the inner grid `<div>` only. The loading indicator ("Loading more videos...") and end-of-list message ("You have reached the end of the video feed.") are rendered as siblings of the grid div inside the section but outside the `aria-live` region. These elements will not trigger screen reader announcements when they appear or disappear.

This deviates from:
- AC 17: loading indicator visually present but not announced to screen readers
- AC 18: end-of-list text is present but not inside `aria-live` as in the blog pattern
- AC 19: loading indicator is not inside a live region

Corrective change: move `aria-live="polite"` from the inner grid `<div>` to the outer `<section>` element in `VideosGridClient` — matching `BlogFeedClient` exactly.

**Severity:** Low  
**Blocks approval:** No

---

### Issue 2 — Double `getAllVideos()` filesystem scan per page request

**Description:** `src/app/videos/page.tsx` calls `getAllVideos()` once directly to extract `featuredVideo`, then calls `getPaginatedVideos()` which also calls `getAllVideos()` internally. Two full directory scans occur per server-side page render. For 82 current video files this is not a performance concern, but it is an avoidable inefficiency.

**Severity:** Low
