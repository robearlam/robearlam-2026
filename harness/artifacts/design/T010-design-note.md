## Title

Homepage v1

---

## Feature Overview

The current homepage is a placeholder. This feature replaces it with a fully designed entry point that introduces the author, surfaces the three most recent blog posts and videos, and conditionally surfaces upcoming speaking engagements — all rendered at build time as a server component. The goal is to give first-time visitors an immediate, well-structured impression of who the site belongs to and what content is available.

---

## Design Intent

- **Entry-point clarity**: The page must communicate the author's identity at a glance. The hero is the primary vehicle for this and should dominate the top of the page without competing with content sections.
- **Content discoverability**: The three curated sections (blogs, videos, speaking) should feel like an editorial index, not a dashboard. Each section is scannable and links out to the full list.
- **Visual restraint**: The design follows the existing typography-led editorial direction. No heavy decoration, gradients, or application-style UI patterns. Spacing and hierarchy carry the visual weight.
- **System alignment**: All visual decisions — typography, spacing, colour, layout width — must use existing design system tokens and Tailwind utility classes. The page should feel native to the existing site.
- **Progressive disclosure**: The hero anchors the identity layer; the content sections reveal depth. The conditional speaking section naturally appears only when relevant, keeping the page tidy.

## Page / Feature Structure

The homepage is a single-column editorial page divided into four structural regions rendered top to bottom:

1. **Hero region** — author identity block with profile photo, name as page `<h1>`, and introductory text
2. **Latest Blogs region** — section heading, three most recent blog post cards, CTA link to `/blog`
3. **Latest Videos region** — section heading, three most recent video cards, CTA link to `/videos`
4. **Upcoming Speaking region** (conditional) — section heading, all upcoming engagement entries, CTA link to `/speaking`

All regions share the same maximum content width container (`max-w-4xl`, centred). Sections are separated by generous vertical spacing rather than dividers or background fills, consistent with the design system's spacing-first separation convention.

The page uses the existing global `SiteShell` layout wrapper (header + footer), so no header or footer design decisions are required here.

## Section Breakdown

### Hero Region

**Purpose**: Establish immediate author identity and set the visual tone for the page.

**Expected content**:
- Author name (`Rob Earlam`) as the page `<h1>`
- Intro/lead text (short biographical or welcome copy)
- Profile photo sourced from `/img/rob.png`

**Visual guidance**:
- At desktop, the hero uses a two-column layout: text column (name + intro) on the left, image on the right. Proportions should weight the text column slightly — roughly 60/40 or equivalent Tailwind fraction split.
- The `<h1>` uses the H1 scale from the design system (36–48px), rendered in the site's primary text colour (`#1F1F1F`).
- The profile photo is rendered as a contained near-square image. A subtle rounded treatment (`rounded-xl` or `rounded-2xl`) is appropriate to soften the photo without overcomplicating the layout.
- Generous top and bottom padding (`py-16` to `py-24`) gives the hero room to breathe and establishes it as the dominant section.
- No background colour, no card treatment — the hero lives directly on the page background.

**Interaction expectations**: None. The hero is purely presentational and static.

---

### Latest Blogs Region

**Purpose**: Surface the three most recent blog posts to drive discovery and engagement.

**Expected content**:
- `<h2>` section heading (e.g. "Latest Writing")
- Three blog post entries, each displaying: title, publish date, abstract
- "View all posts" CTA link navigating to `/blog`

**Visual guidance**:
- The heading follows the H2 scale (30–36px), clearly subordinate to the hero `<h1>` but dominant within its section.
- Blog post cards are rendered in a responsive grid. At desktop, three columns; at mobile, a single stacked column. Cards use the `BlogPostCard` component already defined in the codebase.
- The CTA link sits below the card grid, aligned consistently (trailing right or centred — consistent with other sections). It should be styled as a plain text link rather than a button, to maintain the editorial aesthetic. The primary brand colour (`#7A1C1C`) may be used for the link text.
- Section top padding separates this region from the hero (`mt-16` to `mt-24`).

**Interaction expectations**: Cards are links to the full post. The "View all posts" link navigates to `/blog`. Standard keyboard focus and hover states apply.

---

### Latest Videos Region

**Purpose**: Surface the three most recent videos, paralleling the blogs section in structure.

**Expected content**:
- `<h2>` section heading (e.g. "Latest Videos")
- Three video entries, each displaying: thumbnail, title, publish date
- "View all videos" CTA link navigating to `/videos`

**Visual guidance**:
- Mirrors the Latest Blogs region in structural rhythm: heading, card grid, CTA link.
- Video cards use the existing `VideoCard` component. Thumbnail images should be rendered via Next.js `<Image>` within the component.
- The heading, grid columns, and CTA positioning should be visually consistent with the Latest Blogs section to create a strong repeating editorial cadence.
- Section top padding matches the blogs region spacing for visual consistency.

**Interaction expectations**: Video cards link to their respective content destinations. CTA navigates to `/videos`.

---

### Upcoming Speaking Region (Conditional)

**Purpose**: Highlight upcoming speaking engagements for visitors who may be interested in attending or following the author's talks. Omitted entirely when no upcoming events exist.

**Expected content** (when rendered):
- `<h2>` section heading (e.g. "Upcoming Speaking")
- All upcoming events, each displaying: event name, session name, location, start date
- "View all speaking" CTA link navigating to `/speaking`

**Visual guidance**:
- When rendered, this section follows the same structural rhythm as the blog and video sections.
- Speaking entries are displayed as a stacked list or simple card list rather than a three-column grid, since the number of items is variable and may be just one or two. A single-column card or a subtle row list pattern is appropriate.
- If the speaking section is absent, no empty container, heading, or placeholder element should appear in the DOM — conditional rendering must be total.
- Section top padding matches the preceding sections.

**Interaction expectations**: "View all speaking" link navigates to `/speaking`. Individual event entries link to `/speaking` (the full speaking page) rather than external URLs, unless the specification directs otherwise.

## Component Recommendations

### Homepage-Specific Components

All homepage-specific presentational components should be placed in `src/components/homepage/`.

- **`HomepageHero`** — A new homepage-specific hero component. This must not alter or extend the generic `HeroSection` editorial component in a breaking way. It accepts author name, intro text, and image props. Internally it composes the two-column layout and renders the profile image using Next.js `<Image>`.
- **`HomepageSection`** — A lightweight section wrapper providing consistent heading, content area, and CTA link structure. Used to wrap the blogs, videos, and speaking regions. Accepts a heading label, an optional CTA link label and href, and children.

### Reused Existing Components

- **`BlogPostCard`** — Existing blog card component. Should be reused without modification if it already exposes title, publish date, and abstract. If adaptation is needed, it should be done via props or a thin wrapper — not by altering the shared component.
- **`VideoCard`** — Existing video card component. Should be reused if it exposes thumbnail, title, and publish date. Same adaptation guidance as `BlogPostCard`.
- **`SiteShell`** — Global layout wrapper (already wraps all pages via the root layout). No change required.

### Design System Primitives

- Tailwind grid utilities (`grid`, `grid-cols-1`, `md:grid-cols-3`) for card grids
- Tailwind spacing tokens (`py-16`, `py-24`, `mt-16`, `gap-6`, `gap-8`) for rhythm and breathing room
- Tailwind typography utilities conforming to the Inter font scale
- Tailwind responsive prefixes (`sm:`, `md:`, `lg:`) for breakpoint adjustments

## Responsive Behaviour

### Mobile (default / `< md`)

- Hero: text block (name + intro) stacks above the profile photo. Full-width, centred or left-aligned text. Photo below text, constrained width.
- Blog and video card grids: single-column stacked list (`grid-cols-1`).
- Speaking entries: single-column stacked list.
- CTA links remain visible and tappable below each section.
- Container padding prevents content from touching viewport edges.

### Tablet (`md`)

- Hero may transition to side-by-side layout at `md` breakpoint, depending on available width. If the photo and text feel cramped at `md`, the stacked mobile layout may persist through to `lg`.
- Card grids transition to two columns (`md:grid-cols-2`) if three columns would be too narrow, or directly to three columns if proportions allow.
- Section spacing remains generous.

### Desktop (`lg` and above)

- Hero: full two-column side-by-side layout. Text left, image right. Proportional split (approximately 60/40).
- Card grids: three-column layout (`lg:grid-cols-3`).
- Content contained within `max-w-4xl`, centred with auto horizontal margins.
- CTA links align to the trailing edge of their content grid.

### Cross-Breakpoint Rules

- No horizontal overflow at any breakpoint.
- `<h1>` and `<h2>` headings must remain legible and maintain clear hierarchy at all sizes.
- Profile photo must never overflow its container or appear distorted.
- Conditional speaking section appears and disappears from the DOM entirely — there is no layout shift or reserved space when absent.

## Accessibility Considerations

- **Heading hierarchy**: One `<h1>` (`Rob Earlam`) in the hero; `<h2>` for each content section heading (`Latest Writing`, `Latest Videos`, `Upcoming Speaking`). No heading levels should be skipped.
- **Profile image alt text**: The Next.js `<Image>` for the profile photo must include a meaningful, non-empty `alt` attribute (e.g. `"Rob Earlam"`). It is not a decorative image.
- **CTA link text**: All "View all" links must have descriptive text — `"View all posts"`, `"View all videos"`, `"View all speaking"` — not generic labels. This ensures screen reader users understand link destinations.
- **Keyboard navigation**: Cards and links must be reachable and operable via keyboard. Focus states must be visible (inheriting from the existing site focus ring styles).
- **Colour contrast**: The brand colour (`#7A1C1C`) used for link text must maintain WCAG AA contrast against the white background. This combination has been used across the site and is part of the design system.
- **Landmark regions**: The main content region is already wrapped by the root layout's `<main>` landmark. No additional landmark landmarks are required within the page itself unless a `<nav>` or `<aside>` is introduced (neither is expected here).
- **Conditional section**: When the speaking section is not rendered, it must be entirely absent from the DOM — no `aria-hidden` containers or hidden headings that could confuse assistive technologies.

## Risks

- **Hero component boundary**: The existing `HeroSection` does not support a profile image. Creating a new `HomepageHero` component is the safe path. Any temptation to modify the shared `HeroSection` risks regressions on the blog, contact, or speaking pages that already use it.
- **Sparse content edge case**: If fewer than 3 blog posts or videos exist in the data layer, the homepage will render fewer than 3 cards. This is acceptable behaviour — the section should render whatever is available rather than suppressing itself. The build agent should confirm this behaviour with the data layer before implementation.
- **Date format consistency**: Blog publish dates, video publish dates, and speaking event start dates may be stored in different formats across the three data layers. A single shared display format should be used across all sections. The build agent should establish this format during implementation planning.
- **Timezone normalisation for upcoming speaking**: The conditional speaking logic compares event start dates against the build date. If dates are stored with timezone information, an inconsistent comparison could cause events to appear or disappear unexpectedly. The build agent must normalise the comparison, ideally to UTC date-only.
- **Card component adaptation**: `BlogPostCard` and `VideoCard` may not expose all the required fields (abstract for blogs; thumbnail for videos). Light wrapper or prop extension may be needed without modifying the shared components in a breaking way.

---

## Open Questions

- **Sparse content fallback**: If fewer than 3 blog posts or videos exist, should the section render all available entries, or should a minimum threshold suppress the section entirely? The design intent favours rendering what exists (no suppression), but this should be confirmed during implementation planning.
- **Date display format**: Should all three sections use a single canonical date format (e.g. `DD MMM YYYY` or `MMMM D, YYYY`)? Consistency is preferred. The build agent should define the canonical format and apply it uniformly.
- **Hero intro copy source**: Should the hero intro text be hardcoded homepage copy, or sourced from an existing biography/content field if the data layer exposes one? If no content source exists, the build agent should use a short fixed copy string as a prop.
- **CTA link placement and alignment**: Should the "View all" CTA links be right-aligned on desktop (trailing the card grid) or centred? The design favours trailing-right alignment to reinforce the editorial pattern, but this should be confirmed during the build stage if there is ambiguity with existing section conventions.
