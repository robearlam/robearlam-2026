## Title

Speaking Engagements Page

---

## Feature Overview

This feature adds a dedicated speaking page that presents upcoming appearances and historical engagements from structured markdown content. The page should give visitors a quick, credible overview of the author's speaking activity while keeping long-term history easy to browse without overwhelming the initial view.

---

## Design Intent

The page should feel editorial, calm, and highly scannable, consistent with the site's content-first design system. The primary design priority is to surface the most immediately useful information first: near-term appearances at the top, historical engagements below, and all key talk metadata visible without extra drilling into detail pages.

The visual treatment should stay lightweight, relying on typography, spacing, subtle borders, and restrained accent usage rather than heavy card chrome or app-style controls. The past-history browsing pattern should reduce visual noise by collapsing year groups by default, while still making expansion obvious and accessible.

## Page / Feature Structure

The page should follow the site's standard page rhythm with a single-column editorial layout and controlled reading width.

Primary structure:

- page header introducing the speaking page
- short intro copy clarifying the page's purpose
- upcoming engagements section
- past engagements section with year-based collapsible groups

The hierarchy should keep the page easy to scan from top to bottom. Upcoming content should be immediately visible without interaction. Past content should remain compact at first load, with each year expandable independently.

---

## Section Breakdown

### Header

Purpose:
Establish the page context and match the tone of the rest of the site.

Expected content:
Page title and a brief introductory sentence or short paragraph explaining that the page collects upcoming and past speaking appearances.

Visual guidance:
Use the established editorial heading hierarchy with generous spacing below the title and restrained supporting text styling.

Interaction expectations:
None beyond normal link behavior if intro copy includes any links.

### Upcoming Section

Purpose:
Highlight future engagements as the highest-priority content on the page.

Expected content:
Section heading followed by a vertical list of engagement rows or lightweight cards. Each item should show event name, session name, location, date range, and optional links for slides and recording.

Visual guidance:
Items should read as structured content entries rather than promotional cards. The event name and session name should create the main hierarchy, with metadata and optional links clearly secondary. Use spacing and subtle separators to distinguish entries.

Interaction expectations:
No expansion is required. Optional resource links should be directly visible and clearly labeled. If there are no upcoming items, show a concise empty state in place of the list.

### Past Section

Purpose:
Provide a compact archive of speaking history without making the page feel overly long.

Expected content:
Section heading followed by year-group accordions ordered newest year first. Each collapsed trigger should show only the year label. Expanded content should reveal that year's engagements in reverse-chronological order.

Visual guidance:
Year triggers should be visually distinct as interactive rows, using a simple chevron or similar indicator and clear boundary styling. Expanded engagement entries should reuse the same presentation pattern as the upcoming list for consistency.

Interaction expectations:
All year groups start collapsed. Users can expand any year independently. If there is no past content, show a concise empty state instead of omitting the section.

### Empty States

Purpose:
Preserve page structure and clarity when either dataset is empty.

Expected content:
Short, plain-language messaging such as no upcoming speaking engagements scheduled or no past speaking engagements available.

Visual guidance:
Keep empty states understated and consistent with the site's muted supporting text styles. They should read as informational copy, not alerts.

Interaction expectations:
None.

## Component Recommendations

- Reuse the site's standard page container and editorial heading patterns for page framing.
- Use a shared engagement item component for both upcoming and past entries so metadata order, spacing, and link treatment stay consistent.
- Use a dedicated year-group accordion component for past engagements, built around native button semantics for the trigger.
- Use a simple empty-state text pattern rather than introducing a new illustration or callout component.
- Use existing link styling conventions for slides and recording links, with labels that remain understandable out of context.

The preferred pattern is a small set of reusable content primitives rather than introducing a new visual subsystem for this page.

---

## Responsive Behaviour

### Mobile

- Maintain a single-column flow with comfortable vertical spacing between sections and engagement entries.
- Keep all engagement details stacked in a readable order with no side-by-side metadata that risks crowding.
- Accordion triggers should span the available width and remain easy to tap.
- Optional links should wrap cleanly without causing horizontal overflow.

### Tablet

- Preserve the single-column reading model, but allow slightly roomier spacing and clearer separation between title, metadata, and resource links.
- Expanded year groups should feel visually grouped without relying on heavy containers.

### Desktop

- Keep content width constrained for readability rather than stretching entries across the full viewport.
- Allow slightly more refined alignment of metadata and link groups where space permits, but do not turn the page into a dense table layout.
- Preserve clear visual distinction between the upcoming list and the archived year groups.

Cross-breakpoint rules:

- No horizontal scrolling.
- Heading hierarchy and metadata order must remain consistent across sizes.
- Date, location, and resource links should remain easy to scan without requiring precise pointer interaction.

---

## Accessibility Considerations

- Use a clear semantic heading hierarchy starting with the page title, then section headings for Upcoming and Past.
- Year toggles must use native button behavior, expose `aria-expanded`, and associate the trigger with the revealed content region.
- Expanded year content should be grouped so assistive technologies can understand each year as a distinct archive section.
- Chevron or other state indicators must not be the only signal of expanded or collapsed state.
- Slides and recording links should use descriptive link text so their destination type is clear without surrounding visual context.
- Focus states must remain visible on accordion triggers and resource links.
- Color contrast should follow the design system's accessible editorial palette, especially for muted metadata and interactive accents.
- Any expand or collapse motion should remain subtle and respect reduced-motion preferences.

## Risks

- If engagement items become visually too card-like or dense, the page could drift away from the site's editorial design language.
- Long session titles, locations, or multiple resource links may create awkward wrapping on smaller screens if spacing and hierarchy are not handled carefully.
- A weak accordion treatment could make the past archive look non-interactive or hide too much information from keyboard and screen-reader users.
- Empty states may feel abrupt if their copy and spacing do not preserve the same section rhythm as populated states.

## Open Questions
