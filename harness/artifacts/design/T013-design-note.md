## Title

Blog Hero Images

---

## Feature Overview

This feature extends blog discovery surfaces so homepage preview cards and blog listing cards include a visual image region for each post. When a post provides a hero image, that image is shown; when it does not, the existing placeholder asset is used so every card presents a complete, intentional preview without changing current selection, ordering, filtering, or metadata content.

---

## Design Intent

The design should strengthen scanability and editorial context while preserving the site’s restrained, content-first feel. Images should support recognition rather than dominate the layout, with typography and metadata still carrying the primary hierarchy. The feature should align with the design system’s editorial approach by using simple card structure, neutral surfaces, consistent spacing, and minimal decoration. Across homepage and listing surfaces, image treatment should feel shared and predictable so users understand that each card represents the same post-preview pattern in different layout densities.

## Page / Feature Structure

The feature augments existing blog discovery cards with a dedicated image region while preserving the current text-content region and navigation behavior. The overall structure remains editorial and section-based rather than app-like:

- homepage latest-blogs section: section heading and intro remain unchanged, while each preview card gains a prominent image block paired with existing metadata and summary content
- blog listing surfaces: each listed post card gains a thumbnail region that sits in clear relationship to the existing title, date, excerpt, and tags
- shared card rhythm: image first, content second, with consistent spacing, clear clickable destinations, and no additional decorative UI layers

The image region should read as part of the card rather than a separate widget. Cards should remain easy to scan vertically on small screens and horizontally balanced on larger screens.

## Section Breakdown

### Homepage Latest Blogs Cards

- Purpose: make the homepage latest-post previews more immediately recognizable and visually engaging without changing which posts are surfaced
- Expected content: one image per card, publish date, title, abstract, and tags
- Visual guidance: image should be the leading card element with a calm, editorial presentation; spacing and typography should continue to prioritize the title and abstract over decorative treatment
- Interaction expectations: the image should link to the same blog destination as the title/card, and the card should still read as a single coherent preview unit

### Blog Listing Cards

- Purpose: improve browsing efficiency across archive, pagination, and filtered listing views by providing a consistent visual thumbnail for every post
- Expected content: one thumbnail per listed post plus the existing metadata set already shown by listing cards
- Visual guidance: thumbnails should be slightly more compact than homepage previews but still large enough to feel intentional and useful; text content should remain readable and not be compressed into narrow columns
- Interaction expectations: thumbnail links should resolve to the same post destination as the associated listing card title or primary card interaction

### Shared Image and Fallback Treatment

- Purpose: ensure every card has a complete visual presentation regardless of whether a post defines `heroImage`
- Expected content: hero image when present, placeholder image when absent
- Visual guidance: placeholder usage should appear deliberate, not like an error state; image framing should be consistent across real and fallback assets so cards do not shift visual structure based on content availability
- Interaction expectations: image loading should preserve layout space so content does not jump noticeably as images appear

## Component Recommendations

- Extend the existing homepage blog preview card pattern rather than introducing a separate hero-image card variant with different hierarchy rules.
- Align blog listing cards to the same image-plus-metadata pattern so homepage and listing surfaces feel related even if their density differs.
- Use the project’s existing container, spacing, typography, and link treatments from the design system, keeping neutrals dominant and accent color limited to existing interactive emphasis.
- Treat the image region as a reusable card sub-pattern with a stable aspect ratio, restrained corners/borders consistent with the current site language, and a fixed place in the card hierarchy.
- Preserve current metadata presentation and tags as supporting text so the title remains the primary text anchor.

---

## Responsive Behaviour

### Mobile

- Cards should stack vertically with the image region above the text region.
- Images should span the available card width and maintain a stable aspect ratio to avoid crowding text.
- Text blocks should remain readable with comfortable spacing, and tags or metadata should wrap naturally without overlapping the image or excerpt.

### Tablet

- Cards may remain vertically stacked or move to a more balanced image-to-content proportion, but the image should still lead the scan path.
- Spacing should increase slightly to preserve breathing room as card width expands.
- The relationship between image, title, and summary should remain obvious without introducing wide empty gaps.

### Desktop

- Homepage cards can support a more spacious editorial composition, with images large enough to add visual interest while preserving readable text width.
- Blog listing cards may use a denser layout than homepage cards, but thumbnails should still feel integrated and not reduced to decorative icons.
- Across both surfaces, layouts should avoid horizontal overflow, preserve content hierarchy, and prevent text from being pushed into cramped columns by large images.

---

## Accessibility Considerations

- Card structure should preserve clear semantic grouping so assistive technologies can understand each post preview as a coherent content unit.
- Image alt text should be meaningful when it conveys post-specific information and should avoid noisy repetition of nearby title text; placeholder behavior should not degrade accessibility quality.
- Keyboard users should be able to reach the image link with the same clarity and visible focus treatment as other card links.
- Added imagery must not reduce text contrast, obscure metadata, or interfere with readable heading and summary hierarchy.
- Reserved image space should reduce disruptive layout shift, which benefits both sighted users and users relying on stable focus/context during page load.

## Risks

- Source hero images may vary significantly in composition or dimensions, which can make card presentation feel inconsistent if the image frame is not kept uniform.
- Listing cards may become text-starved on smaller breakpoints if thumbnail sizing is too aggressive.
- Placeholder treatment may feel accidental if it does not share the same framing, sizing, and spacing rules as real post imagery.
- Accessibility could regress if image alt behavior duplicates adjacent link text or if added link targets create confusing focus order.
