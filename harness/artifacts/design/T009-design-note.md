## Title

Videos Listing Page

---

## Feature Overview

Create a dedicated `/videos` page that presents published YouTube videos in a calm, editorial listing. The page should make the newest video immediately visible as the primary item while keeping the rest of the catalogue easy to scan and maintain through file-based content.

---

## Design Intent

The page should feel consistent with the site’s content-first editorial design: restrained, readable, and structured primarily through typography and spacing rather than decorative UI. The main design priority is a clear hierarchy between the newest featured video and the supporting video cards beneath it, without making the page feel application-like or visually heavy.

The layout should stay within the existing design system by using neutral surfaces, muted metadata, strong heading hierarchy, and moderate content widths. The YouTube embeds are the dominant media element, but titles and dates should remain legible and well-spaced so the page still reads as curated editorial content rather than a dense gallery.

Usability should emphasize straightforward browsing. Users should be able to identify the latest video quickly, understand publication recency from date metadata, and move through the remaining videos comfortably across mobile and desktop layouts.

## Page / Feature Structure

The videos page should use a simple single-column page structure within the site’s standard page shell. The content hierarchy should be:

- page heading and brief contextual introduction
- featured video section for the newest item
- supporting videos section for the remaining items
- empty state message when no valid videos are available

The overall layout should remain centered with readable content width. The featured section should read as the editorial lead story for the page, while the supporting section should behave like a secondary collection with consistent cards arranged in a responsive grid.

### Supporting Videos Region

Purpose:

Expected content:

- embedded player for each item

Purpose:

## Component Recommendations

The design should be implemented through a small set of reusable presentation roles rather than embedding all layout decisions directly in the route.

- A page-level videos composition pattern should handle the header, featured region, supporting region, and empty state hierarchy.
- A featured video card pattern should express the lead treatment with larger media, stronger heading scale, and slightly more generous spacing.
- A standard video card pattern should provide the repeated supporting treatment with consistent embed framing, title styling, and muted metadata.
- A simple empty-state pattern should reuse existing site typography and spacing conventions rather than introducing a new visual system.
- Shared typography, container, spacing, and card primitives should follow established design-system patterns so the page feels native to the rest of the site.

If implementation prefers one configurable video card pattern with featured and standard variants, that remains aligned with the design intent as long as the hierarchy remains obvious.

## Responsive Behaviour

### Mobile

- The page should remain a single-column flow.
- The featured video should appear directly below the header with clear spacing and full-width media within the content container.
- Supporting videos should stack in a single column to preserve readable titles and comfortable touch-target separation around interactive embeds.
- Typography and metadata spacing should prevent the page from feeling crowded beneath multiple embedded players.

### Tablet

- The featured section should remain dominant, with spacing scaled up from mobile.
- Supporting videos may move to a two-column grid if card width remains sufficient for readable titles and stable embed proportions.
- Gaps between cards should expand consistently with the site spacing scale rather than introducing dense masonry behavior.

### Desktop

- The page should retain a centered editorial container rather than expanding to a full application-width layout.
- The featured video should read as the clear lead item, using wider media and stronger text hierarchy.
- Supporting videos should present in a multi-column grid where card widths remain balanced and readable.
- The layout should avoid overly wide line lengths or stretched media that reduce visual cohesion.

Cross-breakpoint rules:

- Prevent horizontal overflow from embeds or metadata.
- Preserve the featured-first hierarchy at every size.
- Do not render an empty supporting grid when only one video exists.
- Keep spacing as the main separator between sections rather than relying on heavy borders or backgrounds.

## Accessibility Considerations

- The page should use a clear semantic heading hierarchy, with one page-level H1 and appropriately ordered supporting headings if section labels are introduced.
- Each embedded YouTube iframe must include a meaningful title derived from the video title.
- Text contrast for titles, metadata, and empty-state messaging should remain within the neutral, high-readability palette defined by the design system.
- Focus indicators for any surrounding interactive elements must remain visible and consistent with the rest of the site.
- The layout should support keyboard users by avoiding confusing nested interactive patterns around embeds.
- Dates and titles should remain readable at small viewport widths without truncation that hides essential meaning.
- Section grouping should be understandable to assistive technologies through semantic structure rather than visual proximity alone.

## Risks

- A page composed of multiple embeds can become visually dense if spacing and card sizing are not handled carefully, especially on mobile.
- The v0 reference may imply a stronger card or media treatment than the site’s restrained design system supports, so hierarchy must come from layout and type rather than decorative styling.
- Inconsistent video titles or malformed dates in content could weaken the clarity of the listing even if the page itself remains structurally sound.
- If too many supporting videos are shown in narrow columns on larger screens, readability and scan quality may degrade.
