## Title

Blog Sidebar Panels — Top Tags and Monthly Archive

---

## Feature Overview

This feature introduces a persistent right-column sidebar to the blog listing page (`/blog`) and all tag listing pages (`/blog/tag/[tag]`). The sidebar contains two discovery panels: a **Top Tags** panel showing the ten most-used tags as plain links, and a **Monthly Archive** panel showing every month that contains at least one post as a link annotated with the post count for that month. A new archive route (`/blog/[year]/[month]`) is introduced to display posts filtered by year and month, following the same page pattern as the tag listing page.

The feature deepens content discovery without changing the primary reading experience. The main content feed retains visual dominance; the sidebar is a quiet, useful companion column.

---

## Design Intent

- Preserve the editorial, content-first aesthetic of the blog. The sidebar must not compete with the main feed for visual attention.
- Use the design system's restrained palette, neutral surfaces, and border-division language to frame the sidebar panels as structural companions rather than decorative additions.
- Both panels should feel typographically consistent with the rest of the site — calm heading labels and readable link lists. The two panels differ in copy treatment: the Monthly Archive panel includes a post count alongside each month/year label (e.g. "March 2026 (4)"); the Top Tags panel shows tag names only, with no count.
- The active tag highlight in the Top Tags panel is the only use of the brand primary colour (#7A1C1C) within the sidebar, reserved to orient the reader to their current location.
- Layout should favour editorial readability: a fixed-width sidebar column (~280px) paired with a fluid main content column allows the feed to breathe without the sidebar growing disproportionately on wide screens.
- The sidebar is a progressive enhancement: fully hidden on small screens, it appears from the `md` breakpoint upward. This avoids layout disruption on mobile without hiding content behind a toggle.

## Page / Feature Structure

The two-column layout applies to three page contexts:

1. **Blog listing page** (`/blog`) — main post feed (left) + sidebar (right)
2. **Tag listing pages** (`/blog/tag/[tag]`) — filtered post feed (left) + sidebar with active tag highlight (right)
3. **Archive listing page** (`/blog/[year]/[month]`) — month-filtered post feed (left) + sidebar (right); no archive entry is highlighted in the sidebar on this page

All three pages share the same two-column grid wrapper and the same sidebar component. The sidebar component is composed of two panels stacked vertically: Top Tags above, Monthly Archive below.

The existing single-column blog listing and tag listing layouts are replaced (from `md` upward) by the two-column grid. Below `md`, the layout is single-column with the sidebar hidden.

### Column Width Ratio

The two-column grid uses a `3/4 + 1/4` ratio approximated as a fixed-width sidebar column:

- Recommended: `md:grid-cols-[1fr_280px]`
- This gives the main feed a fluid, content-appropriate width while keeping the sidebar narrow and unobtrusive
- On the widest viewports the sidebar remains at 280px; the feed takes all remaining space within the page container

## Section Breakdown

### Main Content Feed (left column)

- Purpose: displays the ordered list of blog post previews for the current context (all posts, tag-filtered, or month-filtered)
- Content: existing post list cards (title, date, excerpt, tag links); no changes to card layout required by this feature
- Visual guidance: unchanged from current implementation; retains full visual weight as the primary reading surface
- Interaction: post cards link to detail pages; tag links within cards navigate to tag listing pages

### Sidebar (right column)

- Purpose: persistent discovery companion visible alongside the main feed
- Content: two panels stacked vertically (Top Tags, then Monthly Archive)
- Visual guidance: the sidebar column has no background fill of its own; individual panels provide their own surface definition via a light border and subtle inner padding
- The sidebar is wrapped in a semantic `<aside>` element with a descriptive `aria-label` (e.g., "Blog navigation")

#### Top Tags Panel

- Purpose: surface the ten most-used tags as entry points into topic-filtered reading
- Content: a panel heading ("Top Tags") followed by a vertical list of up to 10 tag links
- Each tag is rendered as a text link navigating to `/blog/tag/[tag]`
- **No post count is shown alongside any tag.** Tags are labels only; the reader navigates directly to the tag page to see how many posts it contains.
- The currently active tag (determined by the current route on a tag listing page) is highlighted using the primary brand colour (#7A1C1C) with a slightly heavier weight to distinguish it beyond colour alone; it should also carry `aria-current="page"` on its link element
- Visual guidance: panel heading in a small, muted style (H4-equivalent, secondary text colour #6B6B6B); tag links in body text colour (#1F1F1F); active tag in #7A1C1C; hover state shifts link to secondary brand red (#B23A3A)

#### Monthly Archive Panel

- Purpose: provide chronological navigation across the full span of published content, with post-count context to help readers gauge content density per month
- Content: a panel heading ("Monthly Archive") followed by a vertical list of month/year links, each annotated with the number of posts published in that month
- **Each entry displays the human-readable month/year label followed by the post count in parentheses** — e.g. "March 2026 (4)". The count is rendered as inline text within the link, visually subordinate to the month/year label (lighter weight or muted colour)
- Each entry is a text link navigating to `/blog/[year]/[month]` with a zero-padded month
- All months with at least one post are listed; none are hidden or paginated
- Visual guidance: same base typographic style as the Top Tags panel; the count suffix "(4)" should be rendered in the secondary text colour (#6B6B6B) to keep it visually quiet relative to the month/year label; no active-state highlighting required on this panel

### Archive Listing Page (`/blog/[year]/[month]`)

- Purpose: filtered view of posts published in a given calendar month
- Structure: identical two-column layout as the tag listing page (same grid, same sidebar)
- The page heading should display the human-readable month/year (e.g., "March 2026") in the same H1 style as tag listing pages
- Empty state: if a valid URL has no matching posts, display an appropriate message (e.g., "No posts found for March 2026.") consistent in typography and placement with the tag page empty state

## Component Recommendations

- **`BlogSidebar`** — a new shared component accepting an optional `activeTag` prop. Rendered inside the right column of all three page types. Composes `TopTagsPanel` and `MonthlyArchivePanel` internally.
- **`TopTagsPanel`** — renders the panel heading and tag link list. Accepts the full sorted tag list and an optional `activeTag` value for highlight logic. Receives tag name strings only — no counts.
- **`MonthlyArchivePanel`** — renders the panel heading and archive link list. Accepts the full sorted list of month/year entries, each carrying the post count for that month. Renders count inline as muted suffixed text.
- **Two-column layout wrapper** — a layout grid component (or a Tailwind-classed wrapper div) using `grid md:grid-cols-[1fr_280px] gap-8` or equivalent. Reused across all three page contexts.
- Panel container styling should follow the design system card/border pattern: `rounded-sm border border-[#E5E5E5] p-4` or the nearest equivalent from the existing component set.
- Panel headings should use the existing small-heading typographic style (H4-equivalent).

## Responsive Behaviour

### Mobile (below `md`)

- The two-column grid collapses to a single column
- The sidebar (`<aside>`) is hidden via `hidden md:block` (or equivalent)
- The main content feed occupies the full container width
- No sidebar content is accessible on mobile; this is intentional (discovery panels are a desktop-first enhancement)

### Tablet (`md` and above)

- The two-column grid activates: `md:grid-cols-[1fr_280px]`
- The sidebar becomes visible
- Both panels are fully readable at tablet widths; post count suffixes in the Monthly Archive remain legible at this size
- Panel heading and link font sizes remain unchanged from desktop

### Desktop

- Layout identical to tablet in structure; the main feed expands to fill available space within the page container
- The sidebar column remains pinned at 280px
- The sidebar does not scroll independently; it is positioned in normal document flow alongside the feed

### Cross-breakpoint rules

- Horizontal overflow must be prevented at all sizes; the sidebar must not cause the page to scroll horizontally
- Heading hierarchy and reading order are preserved across all breakpoints
- The sidebar panels must not wrap or collapse in unexpected ways between `md` and `lg`

## Accessibility Considerations

- The sidebar is wrapped in `<aside aria-label="Blog navigation">` to give assistive technologies a meaningful landmark
- Panel headings use an appropriate heading level that maintains document hierarchy without skipping levels (H2 or H3 within the sidebar, below the page H1)
- All tag and archive links must carry meaningful, descriptive text (tag name; human-readable month/year label with count) — no generic "click here" or icon-only links
- The active tag in the Top Tags panel must carry `aria-current="page"` on its anchor element so screen readers announce the current location
- The active tag is distinguishable by both colour and font weight, satisfying WCAG 1.4.1 (use of colour)
- Focus states on all tag and archive links must follow the site-wide visible focus ring pattern
- The Monthly Archive link list must be rendered as a semantic list (`<ul>`/`<li>`) for assistive technology navigation
- The Top Tags link list must also be a semantic list (`<ul>`/`<li>`)
- The post count suffix in Monthly Archive entries is rendered as plain inline text within the link's accessible name; screen readers will announce the full label naturally (e.g. "March 2026 (4)"). No additional `aria-label` override is needed.
- Colour contrast for tag and archive links (#1F1F1F on #FFFFFF) meets WCAG AA; the secondary text colour (#6B6B6B) used for panel headings and post count suffixes should be verified at their actual rendered sizes and replaced with a darker muted tone (e.g., #4B4B4B) if contrast is insufficient for small text
- The `hidden md:block` pattern ensures the sidebar does not inject hidden interactive elements into the mobile tab order

## Risks

- The secondary text colour (#6B6B6B) used for panel headings and Monthly Archive count suffixes may fall below WCAG AA contrast for small text sizes. These elements should be tested at their actual rendered size; if contrast is insufficient, use #4B4B4B or a similar darker muted tone.
- If the tag listing page layout is tightly coupled to a single-column structure, introducing the two-column grid wrapper may require non-trivial refactoring that increases layout complexity beyond what the design assumes.
- The Monthly Archive panel length is unbounded — sites with many years of posts could produce a very long list. For the current scope this is accepted as-is (no truncation or pagination), but it may become a UX concern over time.
- On narrow tablet viewports (close to the `md` breakpoint), the 280px sidebar may feel crowded against the main feed, particularly in the Monthly Archive where each entry now includes a count suffix. Implementors should verify readability at the `md` breakpoint and adjust the gap or sidebar width if needed.
- Per-month post counts require an aggregate data pass at build time; if this is expensive or complex, implementation may need to cache or co-locate this computation with the tag count aggregation already expected to exist.
