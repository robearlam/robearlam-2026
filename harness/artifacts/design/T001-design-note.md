## Title

Global Site Layout

---

## Feature Overview

This feature defines the shared page shell for the Next.js App Router so all standard site pages inherit the same header, navigation, centered content area, and footer.

The layout establishes the structural baseline for the rest of the site. Its purpose is to make movement between pages predictable, keep content readable, and ensure future pages can plug into a consistent shell without repeating layout decisions.

---

## Design Intent

The layout should feel calm, structured, and content-first. The shell should support the design system by relying on neutral backgrounds, restrained use of brand color, clear borders or separation where helpful, and a consistent centered container width near 1100px.

The primary design priorities are:

- immediate orientation through a stable header and navigation area
- strong readability through centered content and controlled line length
- minimal visual complexity so future page content remains the focus
- a responsive shell that stays usable on small screens without horizontal overflow
- semantic structure that makes the page regions obvious to both users and assistive technology

This feature should solve layout consistency, not introduce elaborate navigation behavior. Visual restraint is preferable to adding decorative treatments or advanced interactions.

## Page / Feature Structure

The shared shell should use a simple vertical page structure:

1. Header region spanning the full page width
2. Inner header container centered to the standard maximum width
3. Main content region that expands to fill available height
4. Inner main container centered to the standard maximum width
5. Footer region spanning the full page width
6. Inner footer container centered to the standard maximum width

The full-width page regions create a stable site frame, while the inner containers preserve readable content width. The header and footer should visually read as shared site chrome. The main region should remain the dominant reading area and should not inherit the current starter-page centering pattern.

Semantic landmarks should be explicit: header, navigation, main, and footer. The page shell should also support short pages by allowing the main region to grow so the footer settles at the bottom without floating midway up the viewport.

## Section Breakdown

### Header

Purpose:

Provide persistent site identity and top-level wayfinding.

Expected content:

- site name or wordmark on the left
- primary navigation adjacent to or opposite the site identity
- optional compact mobile navigation trigger if the chosen responsive pattern needs it

Visual guidance:

- full-width region with a subtle bottom border or separation from page content
- neutral surface treatment with restrained use of brand color for active or emphasized states
- vertical padding large enough to feel deliberate, but not oversized relative to the content-first goal

Interaction expectations:

- the header remains visible at the top of every standard page
- primary navigation labels are simple and flat, with no requirement for nested menus in this slice

### Navigation

Purpose:

Expose a small, clear set of top-level destinations that is available on every page.

Expected content:

- a short list of top-level links
- active-page indication

Visual guidance:

- desktop presentation should be direct and lightweight, such as an inline horizontal link row
- active state may use the brand red as a restrained accent, supported by font weight or underline treatment rather than heavy fills
- avoid dropdown or mega-menu patterns for this slice

Interaction expectations:

- links must remain keyboard accessible and easy to target
- if a mobile toggle is used, it should reveal the same flat navigation set rather than a different information architecture

### Main Content Region

Purpose:

Provide a stable centered container for all page-specific content.

Expected content:

- routed page content supplied by child pages

Visual guidance:

- main content uses the standard centered container with maximum width around 1100px
- container padding should protect content on narrow screens and create comfortable breathing room on larger screens
- the main region should avoid hard centering of all child content; page content must be able to establish its own layout inside the shared shell
- section spacing should follow the design-system rhythm using repeated spacing values rather than ad hoc gaps

Interaction expectations:

- the shell should not constrain page-level interaction patterns beyond consistent horizontal bounds and vertical spacing

### Footer

Purpose:

Close the page with a consistent end-of-page region and provide persistent structural context.

Expected content:

- simple footer copy, such as owner or site attribution
- optional small set of secondary links if available

Visual guidance:

- full-width region separated from main content with a top border or spacing break
- quieter visual weight than the header
- compact but readable spacing

Interaction expectations:

- links, if present, should remain simple and keyboard accessible
- placeholder content is acceptable for this slice if final copy is not yet approved

## Component Recommendations

This feature should prefer existing primitives and simple reusable patterns over bespoke layout elements.

- Use standard layout wrappers to create repeated centered containers for header, main, and footer regions.
- Use a simple navigation link list as the baseline pattern for top-level navigation. The current navigation primitive library is available, but the layout does not require dropdown behavior or multi-level navigation for this task.
- Use existing button primitives only if a compact mobile navigation trigger is needed.
- If mobile navigation needs an overlay or slide-in panel, prefer the existing sheet primitive rather than introducing a custom drawer pattern.
- Keep brand color usage limited to active navigation states, focused elements, and small accents rather than large filled surfaces.

The design goal is reusable shell structure, not a complex navigation component system.

## Responsive Behaviour

### Mobile

- The shell should keep the same structural order: header, main, footer.
- Horizontal padding should increase content safety so text and links do not touch the viewport edge.
- Primary navigation must remain discoverable without causing wrapping that makes the header unreadable.
- If the top-level links cannot fit comfortably in one row, use a simple toggle or sheet pattern instead of squeezing or truncating labels.
- Main content should remain readable without horizontal scrolling.

### Tablet

- Container width should continue to center content with moderate side padding.
- Navigation may remain inline if space allows, but spacing should not become so wide that the header feels sparse.
- Vertical rhythm between header, content, and footer should remain consistent with the desktop structure.

### Desktop

- Header and footer remain full width, with inner content constrained to the standard maximum width.
- Primary navigation should be visible without a toggle in the normal desktop layout.
- The main container should preserve readable line lengths and prevent content from stretching too wide.

Cross-breakpoint rules:

- no horizontal overflow in standard page shell regions
- maintain readable content width inside the main container
- preserve semantic and visual hierarchy across all viewport sizes
- keep navigation content functionally equivalent across breakpoints

---

## Accessibility Considerations

- Use semantic landmarks so header, nav, main, and footer are programmatically identifiable.
- Ensure keyboard users can reach navigation links and any mobile navigation trigger in a logical order.
- Maintain visible focus states that are distinguishable from hover-only styling.
- Use sufficient contrast for text, borders, and active navigation indicators.
- Preserve a logical heading hierarchy within page content; the shared layout should not interfere with page-level heading structure.
- If a mobile navigation sheet or toggle is used, it must support focus management, dismiss behavior, and accessible labeling.
- Avoid relying on color alone for current-page indication when a secondary cue such as weight, underline, or position can reinforce it.
