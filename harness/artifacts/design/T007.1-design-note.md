## Title

Blog Sidebar Refinements

---

## Feature Overview

This feature refines blog discovery and reading comfort by grouping archive links under year headings, presenting top tags as compact wrapping chips, and widening the shared content container so editorial content feels less constrained.

---

## Design Intent

The design should make archive navigation easier to scan, reduce sidebar visual heaviness, and improve reading comfort without changing the site’s calm editorial character. The archive panel should emphasise chronological structure first, the tag panel should become denser without becoming noisy, and the wider shared container should preserve readable line lengths while reducing the cramped feel of the current layout. All changes should remain restrained, typography-led, and consistent with the existing neutral palette and minimal accent usage.

## Page / Feature Structure

The feature keeps the existing blog page and archive layout structure, but refines three regions within it:

- the shared page shell, with a wider central content container applied consistently across pages using the common layout
- the Monthly Archive sidebar panel, reorganised into descending year groups with linked year headings above their month links
- the Top Tags sidebar panel, reorganised from a stacked list into a wrapping chip row that still reads as a navigational collection

The new year archive page should follow the same archive-listing page structure already used by blog archive views so users encounter a familiar heading, post list, and empty-state treatment.

## Section Breakdown

### Shared Content Container

Purpose:

Increase reading comfort and reduce the squashed feel of long-form content across all pages using the shared shell.

Expected content:

Primary page content remains dominant, with the sidebar retaining a secondary supporting role.

Visual guidance:

The width increase should be noticeable but restrained. Content should still sit within a centered, editorial-style measure rather than feeling full-bleed or application-like.

Interaction expectations if applicable:

No new interaction. The refinement is spatial and should preserve current page flow and hierarchy.

### Monthly Archive Panel

Purpose:

Make chronological browsing easier by surfacing years as the primary grouping and months as secondary links.

Expected content:

Each year heading shows the year label and total post count, ordered newest to oldest. Month links appear beneath each heading in descending order.

Visual guidance:

Year headings should read as lightweight subheads or grouped labels, visually distinct from month entries without becoming dominant. Counts should be secondary in tone. Month links should remain compact and easy to scan.

Interaction expectations if applicable:

The year heading itself is the navigation affordance to the year archive. Month links continue to navigate to monthly archives. Active states should remain clear for both year and month contexts where relevant.

### Top Tags Panel

Purpose:

Present high-value tags in a denser, more glanceable format.

Expected content:

Each chip includes the tag label and count, preserving existing ranking and linking behaviour.

Visual guidance:

Chips should use a restrained pill or badge treatment with small radius, subtle border or surface definition, and compact spacing. The panel should feel editorial and calm rather than playful or app-like.

Interaction expectations if applicable:

Each chip remains individually clickable, with active-state styling still clearly visible when the current page matches the tag.

### Year Archive View

Purpose:

Provide a year-level archive destination that sits naturally between the blog index and month-level archive pages.

Expected content:

The page presents the selected year as the archive context and lists posts from that year using the same listing pattern as other archive views. If no posts exist for a valid year route, an explicit empty state appears in the main content area.

Visual guidance:

The page should look like an archive variant, not a new page type. Heading, metadata rhythm, spacing, and list treatment should match existing archive conventions.

Interaction expectations if applicable:

Users should be able to move between year and month archive destinations through the sidebar without needing to relearn navigation patterns.

## Component Recommendations

- Reuse the shared shell or container pattern already applied across blog and related pages, adjusting width centrally rather than introducing page-specific layout variants.
- Reuse the existing sidebar panel structure for both archive and top-tag sections so only the internal item layout changes.
- Treat year headings as standard text-link navigation elements within the archive panel rather than introducing a new accordion or disclosure system.
- Reuse the established archive listing pattern for the year archive page, including the existing empty-state style and list presentation.
- Reuse the current active-state treatment for tag and archive navigation, adapting it to chip presentation and year-link contexts.

## Responsive Behaviour

Describe how the feature should behave across screen sizes.

Include guidance for:

### Mobile

- The wider shared container should still preserve comfortable side padding and avoid edge-to-edge text blocks.
- Year groups should stack cleanly with clear spacing between headings and month links.
- Tag chips should wrap naturally into multiple rows without horizontal overflow or clipped counts.

### Tablet

- The increased content width should become more apparent while preserving a clear separation between main content and sidebar.
- Archive year groups should remain easy to scan as a vertical sequence.
- Tag chips may fill rows more densely, but spacing should remain readable and not collapse into a solid block.

### Desktop

- The shared layout should provide a visibly wider main reading column while keeping the sidebar proportionally secondary.
- Archive panel hierarchy should be clear at a glance, with year headings anchoring each group.
- Tag chips should form a compact cloud-like grouping that uses horizontal space efficiently.

Include any important cross-breakpoint rules such as:

- preventing horizontal overflow in the tag panel
- preserving clear hierarchy between year headings and month links
- maintaining readable line lengths in the widened content column

## Accessibility Considerations

- Preserve clear semantic heading hierarchy on archive pages so the year archive view fits naturally into existing page structure.
- Ensure year links, month links, and tag chips remain keyboard reachable with visible focus states.
- Do not rely on color alone for active-state communication; active items should remain distinguishable through weight, border, background, or similar non-color cues already used by the system.
- Keep text contrast strong for counts, metadata, and chip labels against neutral surfaces.
- Maintain sufficiently large tap targets and spacing for wrapped chips on touch devices.
- Ensure grouped archive content remains understandable to assistive technologies as a sequence of year groupings with associated month links.

## Risks

- A width increase that is too aggressive could weaken readability on large screens, so the change should widen the layout without losing editorial measure.
- If year headings become too visually prominent, the archive panel could feel heavy instead of lightweight and scannable.
- Wrapping chips may produce awkward density or uneven rows at narrower widths if spacing is not kept disciplined.
