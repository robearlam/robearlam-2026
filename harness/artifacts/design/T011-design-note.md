## Title

SEO, AEO, and GEO Foundations

---

## Feature Overview

This feature establishes consistent, site-wide search and machine-readability foundations so every public route is discoverable and understood by both traditional search crawlers and AI retrieval systems.

The design scope covers metadata consistency, structured data presence, crawler-facing discoverability surfaces, and visible page-level clarity signals that improve answer extraction and citation quality.

---

## Design Intent

The experience objective is trust and clarity: each page should communicate purpose immediately to users while exposing equivalent meaning to machines.

Design priorities:

- preserve the existing editorial, content-first page experience
- make SEO/AEO/GEO cues visible but unobtrusive
- keep information architecture predictable across page types
- ensure machine-readable metadata aligns with what users see

Alignment with the design system:

- maintain restrained visual treatment and typography-led hierarchy
- use spacing and semantic structure rather than decorative containers
- keep summaries and identity signals concise, readable, and integrated into normal content flow

Usability considerations:

- users should quickly understand page purpose from above-the-fold context
- share previews should reflect on-page meaning consistently
- no additional cognitive load from SEO-oriented content blocks

## Page / Feature Structure

The feature design is cross-cutting and applies a shared semantic pattern to all key route types (home, blog post, videos, speaking, contact):

1. Identity and intent region near the page top.
2. Primary content region with strong heading hierarchy.
3. Optional route-specific structured context (post, video, event) represented consistently in visible content.
4. Stable canonical ownership cues through page-level source clarity.

At the site level, discoverability surfaces (sitemap and crawler policy) are treated as foundational system outputs that map directly to the same route hierarchy users navigate.

## Component Recommendations

- Reuse existing page-level heading and intro composition patterns for top-of-page summaries rather than introducing new visual modules.
- Reuse established metadata/text treatment for author/entity context to keep identity cues consistent.
- Use existing content section wrappers and spacing rhythm to enforce semantic section boundaries across route types.
- Keep structured-data-backed content tied to visible sections already present in each page template.
- Continue using current global navigation and hub-page linking patterns to maintain crawler and user discovery paths.

## Responsive Behaviour

### Mobile

- Keep summary and identity context directly below the page title to avoid hidden critical context.
- Maintain single-column reading flow with consistent vertical spacing.
- Preserve readable line length and prevent metadata rows from wrapping into ambiguous label/value groupings.

### Tablet

- Maintain primary single-column editorial flow with slightly expanded spacing.
- Allow route metadata groupings to sit inline only when readability remains clear.

### Desktop

- Preserve centered readable content width (editorial container sizing).
- Allow supporting identity/context details to align with heading regions without creating multi-column reading fragmentation.

Cross-breakpoint rules:

- avoid horizontal overflow in metadata and summary regions
- preserve heading hierarchy and section order consistently
- keep summary and identity signals above major route-specific content sections

---

## Accessibility Considerations

- Preserve semantic landmarks and heading order on all key routes.
- Ensure summary and identity blocks are plain text and readable by assistive technology in natural reading order.
- Maintain sufficient contrast for supporting text styles used in metadata and summaries.
- Do not encode meaning through color alone for identity or status cues.
- Ensure any linked identity/source cues remain keyboard accessible with visible focus indication.
- Keep section labeling explicit so assistive technology users can navigate route-specific content chunks reliably.
