## Title

Blog Post Disqus Comment Integration

---

## Feature Overview

Add a Disqus comments section to individual blog post pages so readers can view the existing discussion for a post and submit new comments without leaving the article.

The feature is bounded to blog detail pages and uses each post's existing `disqusId` as the canonical thread identifier.

---

## Design Intent

The comments experience should feel like a natural continuation of the editorial reading flow rather than a separate application surface.

Design priorities are:

- preserve the existing article-first hierarchy
- place comments clearly after the post content with calm, unobtrusive separation
- align with the site's restrained editorial design system using spacing, typography, and neutral surfaces rather than heavy framing
- make the discussion area feel discoverable without competing with the article itself
- ensure the embedded interaction remains readable and usable across screen sizes

## Page / Feature Structure

The feature extends the existing blog detail page only.

The page structure should remain:

- post header and metadata
- post body content
- comments section beneath the article content

The comments section should appear as the final major content region within the main reading column, separated from the post body by generous vertical spacing and a light structural cue such as a section heading and optional subtle divider.

---

## Section Breakdown

### Comments Section Wrapper

- purpose: define a clear transition from article reading to discussion
- expected content: section heading, optional short supporting line if needed by the existing page pattern, and the Disqus embed area
- visual guidance: use the same centered content width as the article column; rely on spacing and simple typography rather than a card-heavy treatment; borders, if used, should be light and minimal
- interaction expectations: no additional controls are needed outside the embedded Disqus experience; the section should load as part of the post page experience

### Comments Heading

- purpose: label the discussion area clearly for scanning users and assistive technology
- expected content: concise heading such as "Comments"
- visual guidance: use the established heading hierarchy below the article title level; keep supporting text muted if present
- interaction expectations: none beyond standard reading flow

### Embedded Discussion Area

- purpose: display the existing thread for the current post and provide the standard Disqus submission flow
- expected content: the embedded Disqus thread tied to the current post's canonical identifier
- visual guidance: allow the third-party embed to remain visually contained within the editorial layout; avoid extra decorative containers that fight the embed's own UI
- interaction expectations: users should be able to read, navigate, and submit comments through the embedded interface on the blog detail page only

---

## Component Recommendations

- Reuse the existing blog detail page content container and spacing rhythm so the comments region inherits the editorial page structure.
- Use the site's standard heading and body text styles for the section label and any supporting copy.
- Treat the comments area as a standard content section rather than introducing a new bespoke comments layout system.
- If a divider is already part of the site's content-section pattern, it is appropriate as a subtle separator before comments; otherwise spacing alone is preferred.

---

## Responsive Behaviour

Describe how the feature should behave across screen sizes.

### Mobile

- keep the comments section in a single column aligned with the article content
- preserve comfortable side padding and avoid horizontal overflow from the embed container
- maintain clear spacing between the end of the article and the discussion heading

### Tablet

- retain the same single-column reading flow
- allow spacing to open slightly while preserving a readable text measure
- keep the comments area visually subordinate to the article body

### Desktop

- keep comments within the established readable content width rather than expanding to a wide application-style panel
- use generous top spacing so the discussion area feels intentionally separated from the article conclusion
- preserve a calm editorial rhythm with heading, spacing, and embedded thread stacked vertically

Include any important cross-breakpoint rules such as:

- prevent horizontal overflow
- preserve heading hierarchy and content order
- keep the comments section within the main content column

## Accessibility Considerations

- The comments region should be introduced with a clear semantic section heading so screen-reader users can understand the transition from article to discussion.
- Heading hierarchy should remain sequential beneath the blog post title.
- Any visible separator before the comments section should remain decorative only and not be relied on as the sole cue.
- The embedded area should have sufficient surrounding spacing and clear visual boundaries so users can distinguish host-page content from the third-party discussion UI.
- Keyboard users must be able to reach the embedded comments area through the normal page tab order.
- Body text, headings, and any supporting copy around the embed should maintain the design system's contrast and readability standards.

## Risks

- The Disqus embed introduces a third-party visual surface that may feel heavier than the surrounding editorial design if not given enough spacing.
- Long embedded thread content may create visual density at the end of the article, especially on smaller screens.
- Posts with missing or incorrect `disqusId` values could create a mismatch between the article and the displayed discussion.
