## Technical Approach

Implement a centralized SEO foundation in the Next.js App Router so metadata, canonical logic, structured data, and crawl/index surfaces are generated consistently from shared utilities and route-level adapters.

Primary approach:

- Establish a single source of truth for site identity and canonical base URL used by metadata, sitemap, robots policy, and JSON-LD output.
- Use Next.js metadata APIs for global defaults and per-route overrides, with route-specific metadata builders for home, blog posts, videos, speaking, and contact pages.
- Add deterministic JSON-LD composition helpers for global (`WebSite` + site identity) and route-specific schema (`WebPage`, `BlogPosting`, `VideoObject`, `Event`) that stay semantically aligned with visible content.
- Add crawler-facing foundation files (`sitemap`, `robots`) that reflect explicit indexability policy and in-scope route coverage.
- Introduce GA4 integration at the app-shell level with environment-safe loading and route-transition-aware pageview dispatch to prevent duplicate firing.
- Apply minimal, explicit page-level summary/entity clarity updates where needed so visible AEO/GEO signals align with machine-readable metadata.

This keeps architecture simple: reusable logic in library utilities, route-specific mapping in route modules, and shared global behavior in the app layout.

## Risks

- Canonical URL or identity configuration drift could create inconsistent metadata/schema outputs.
- Route content variability (especially videos and speaking data richness) may require conditional schema handling to avoid invalid payloads.
- Analytics integration at layout level may introduce duplicate pageviews if navigation hooks are not centralized correctly.
- Robots policy misconfiguration could unintentionally reduce search/AI crawler visibility.
- Summary/entity updates could unintentionally diverge from existing route copy if not validated against visible content.
