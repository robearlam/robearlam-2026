## Technical Approach

Implement the feature by extending the existing blog archive and sidebar patterns rather than introducing new structures. The blog post query layer should remain the central source for archive derivation and filtering, adding year-level aggregation and year-only filtering alongside the current month archive support. A new `/blog/archive/[year]` route should mirror the current archive and tag listing pattern, including static params, metadata, pagination inputs, and empty-state behavior, so archive views stay consistent.

Sidebar refinements should be delivered by adapting the current panel components in place. The Monthly Archive panel should render descending year groupings with linked year headings and nested month links derived from shared archive data. The Top Tags panel should keep its current behavior and active-state semantics while switching to a wrapped chip presentation. The wider content column should be applied at the shared shell level so blog and other pages using the same shell inherit the width adjustment without page-specific overrides.

5. Apply the width adjustment at the shared shell or container level, then verify that blog index and archive pages continue to use the same two-column layout with a visibly wider main reading column.

## Risks

- The existing archive utility types may assume month-specific entries, so introducing grouped year data may require careful type changes to avoid duplicating archive logic.
- If the year archive page diverges from the existing archive listing pattern, archive views could become inconsistent in pagination or empty-state behavior.
- Widening the shared shell may affect non-blog pages that use the same container, so the change should be restrained and validated beyond a single route.
- Wrapping tag chips may expose spacing or overflow issues at narrower widths if chip sizing is not kept compact.
