## Technical Approach

Implement a new static contact route under the App Router that automatically inherits the existing shared shell from T001 (`SiteShell` through root layout). Keep the page server-rendered and content-first, with no client-side state, no form controls, and no submission logic.

Use a simple semantic structure in a single-column flow:

- header block (H1 + short introduction)
- direct contact methods block (static text/link content)
- external profile links block (required destinations only)

Represent profile links through a small page-local data structure to reduce copy/paste risk and keep URL/icon/label mappings explicit and auditable. Use recognizable icons via the project's existing icon approach and pair each icon with visible text to satisfy recognizability and accessibility constraints.

Align layout and typography with existing route conventions (`Home` / `About`) and shell container behavior so readability and responsive behavior are consistent without introducing new design-system abstractions.

## Implementation Steps

1. Create `src/app/contact/page.tsx` with semantic static structure: H1, short intro, direct contact methods section, and external profiles section.
2. Add a `Contact` item to shared navigation in `src/components/site-nav.tsx` so the route is discoverable within the shell patterns used by existing pages.
3. Define the six required external profile entries in a single local data structure in the contact page and render them consistently with icon + visible label + secure external-link attributes.
4. Ensure the contact methods content remains static and non-interactive beyond optional direct links (e.g., `mailto:`); do not add any form fields, submit controls, or submission logic.
5. Apply existing typography/spacing/container conventions from current pages and shell so mobile/desktop readability remains consistent and avoids horizontal overflow.
6. Add integration tests to validate presence of heading, intro, static contact method content, required external links, accessible names, and absence of form submission UI.
7. Add e2e tests for contact-page rendering on desktop/mobile, required link behavior and attributes, and overflow/readability checks.
8. Run project validation commands relevant to this change set (lint, typecheck, unit/integration, e2e) and resolve any regressions introduced by the feature.
