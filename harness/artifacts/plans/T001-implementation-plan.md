## Technical Approach

Implement the shared shell in the existing Next.js App Router root layout so all app routes inherit a consistent structure by default.

Use a simple, semantic page frame with full-width header and footer regions and centered inner containers for header, main, and footer content at approximately 1100px max width. Keep the layout content-first and neutral, with restrained accent usage for navigation active state and focus visibility.

Replace the current starter-page full-screen centering pattern with shell-compatible page content behavior so route pages can define their own internal layouts within a stable outer container.

Start with a lightweight global navigation pattern (small top-level link set, accessible keyboard behavior, clear current-page indication). If small-screen space cannot support inline navigation without poor wrapping, use existing primitives for a compact toggle/sheet pattern rather than introducing bespoke navigation architecture.

Keep implementation aligned with existing stack conventions (Tailwind + App Router), avoid unnecessary abstraction, and introduce reusable layout pieces only where they reduce duplication and improve clarity.

## Implementation Steps

1. Confirm root layout composition strategy for semantic regions and centered container wrappers aligned to design-system width guidance.
2. Update root layout to render shared header, navigation, main content container, and footer for inherited routes.
3. Define an initial, reviewable top-level navigation set and implement active-link indication using restrained visual emphasis and non-color cueing.
4. Apply responsive layout behavior so navigation remains discoverable and readable on narrow screens; introduce toggle/sheet only if inline links become unreadable.
5. Update starter route content patterns that currently force full-screen centering so page-level content can flow naturally inside the shell.
6. Refine global styling (spacing rhythm, separators, container padding) to match design-system and design-note guidance while avoiding unnecessary custom CSS complexity.
7. Add integration and/or e2e tests that validate shell presence, navigation accessibility, footer visibility, and no-overflow behavior across representative viewport widths.
8. Run project lint/test checks for modified scope and resolve in-scope issues before handoff to QA.
