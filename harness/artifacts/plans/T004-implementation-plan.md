## Technical Approach

The refactor re-skins the existing production site to align with the editorial design system defined in `harness/design-system/design-system.md`. The approach preserves the current application architecture (Next.js App Router, `src/components/`, `src/app/` layout), existing routing, data-fetching logic, and all tests.

**Font swap.** The root layout switches from Geist to Inter using `next/font/google`. CSS custom properties and Tailwind font configuration are updated accordingly.

**Container width strategy.** The main content container inside `site-shell.tsx` is narrowed to a `max-w-3xl`-to-`max-w-4xl` range to enforce readable line length. The header and footer inner containers retain `max-w-[1100px]` so that navigation and footer content have comfortable horizontal space and the existing integration test assertion (`container.innerHTML` contains `max-w-[1100px]`) continues to pass without modification.

**Component architecture.** A small set of reusable editorial components is introduced under `src/components/editorial/`:

- `section-wrapper.tsx` — applies section-level vertical spacing.
- `hero-section.tsx` — renders an H1 heading and lead paragraph.
- `content-block.tsx` — standard prose container.

These are lightweight wrappers using Tailwind utility classes. No new UI library is introduced.

**Header and navigation.** The existing `site-shell.tsx` header is restyled to match the editorial design (white surface, subtle border, text-based site identity). `site-nav.tsx` is updated so that on mobile, navigation links are hidden behind a hamburger toggle button. The `<nav>` element with `aria-label="Mobile primary navigation"` remains visible on mobile at all times (it contains the toggle button), preserving the E2E test expectation. Active-link styling uses the dark red accent (`#7A1C1C` / `text-primary`) with an underline cue.

**Footer.** The footer section within `site-shell.tsx` is simplified to a minimal copyright line, optionally with inline navigation links. No multi-column layout or social icons.

**Page-level updates.** Each page (`/`, `/about`, `/blog`, `/blog/[slug]`, `/blog/tag/[tag]`, `/contact`) is updated to compose from the editorial components with consistent typography and spacing. Blog data logic, API routes, and markdown rendering remain untouched — only presentation classes change.

**Colour and typography.** The CSS custom properties in `globals.css` already align with the design system palette. The body and heading typography classes are updated to match the design system scale (H1 36–48px, H2 30–36px, H3 24–28px, body 16–18px). Updates are applied through consistent Tailwind classes on page and component elements.

## Risks

1. **Integration test asserts `max-w-[1100px]`**. The integration test for the global layout explicitly checks that `max-w-[1100px]` appears in the rendered HTML of `SiteShell`. The mitigation strategy — keeping `max-w-[1100px]` on header/footer inner containers while narrowing the main content container — should satisfy both AC 1 (narrower content width) and AC 15 (tests pass). If the Build Agent finds this approach insufficient, escalate before modifying tests.

2. **E2E test expects mobile navigation visible immediately**. The E2E test checks `page.getByRole("navigation", { name: /mobile primary navigation/i })` is visible on a 375px viewport. The mobile hamburger toggle must be implemented so the `<nav>` element itself remains visible (containing the toggle button), even when the link list is collapsed. If the toggle implementation hides the entire `<nav>`, the test will fail.

3. **Mobile hamburger requires client-side state**. The `site-nav.tsx` is already a `"use client"` component. The hamburger toggle adds a boolean state. This is minimal and consistent with the design note guidance, but care is needed to ensure server-side rendering is not disrupted.

4. **Scope creep from "real content" requirement**. The homepage and about page need real, representative content rather than placeholder text. The Build Agent should write concise, authentic content aligned with the site's professional context. Content length should not expand scope.

5. **Blog card styling changes**. Flattening blog post cards from bordered card styling to editorial spacing/dividers changes the visual presentation significantly. The `data-testid="blog-post-card"` attribute and the article element structure must be preserved for the E2E infinite-scroll test.

6. **Contact page icons**. The contact page currently uses `react-icons` for social profile icons. The design note does not mention icons. Removing them would be a simplification. However, the contact integration test checks for link text (e.g. `screen.getByText(label)`) and the E2E test checks for link role by name — icon removal should not affect test results, but the page must retain all six profile links with exact `href`, `target`, `rel`, and `aria-label` values.
