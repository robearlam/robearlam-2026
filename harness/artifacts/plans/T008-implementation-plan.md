## Technical Approach

The feature adds a `/speaking` page that loads speaking engagement data from structured markdown front-matter files under `src/data/speaking/YEAR/` at build time, then renders two sections — Upcoming and Past — according to the approved spec.

### Data Layer

Follow the same pattern established by `src/lib/blog/`: define TypeScript types and a dedicated loading module in `src/lib/speaking/`. Use Node `fs` and `gray-matter` (already in use for blog content) to read and parse the front-matter-only markdown files. Validate required fields and reject malformed records cleanly. All date comparisons should use the date at server-render time (Next.js generates this as a server component, so the build/request date is appropriate).

### Partitioning and Sorting

After loading all engagement records, partition into upcoming (start date ≥ today) and past (start date < today). Sort upcoming ascending by start date. Sort past descending by start date, then group by year, with year groups sorted descending by year. Use filename-stable sort order as the tiebreaker for identical start dates.

### Page and Component Layer

The page route itself (`src/app/speaking/page.tsx`) will be a server component that calls the data loading function, partitions the results, and passes data to the section components. No interactivity is needed at page level.

The Past section's year-group accordion requires client-side toggle state. Implement a thin client component for the accordion trigger/panel pattern; all year groups start collapsed. Use native `button` semantics with `aria-expanded` and an associated content region. shadcn/ui's Accordion component (already in the project's component library) is an appropriate primitive for this if available; otherwise implement with a minimal bespoke client component.

The engagement item layout (name, session name, location, dates, optional slide/recording links) should be a shared presentational component used by both the Upcoming and Past sections to keep rendering consistent.

The page follows the site's single-column editorial layout already established in `src/app/blog/page.tsx` — an `<h1>` page header, brief intro copy, then the two sections.

## Test Plan

### Unit Tests — `src/app/tests/unit/speaking-engagements.test.ts`

- `normalizeSpeakingEngagement` returns null for a record missing any required field (`name`, `sessionName`, `location`, `start`).
- `normalizeSpeakingEngagement` returns null for an invalid `start` date string.
- `normalizeSpeakingEngagement` returns null when `end` is earlier than `start`.
- `normalizeSpeakingEngagement` returns a valid object when all required fields are provided and optional fields are absent.
- `normalizeSpeakingEngagement` returns a valid object when all fields including optional ones are provided.
- `partitionEngagements` places engagements with future start dates in the upcoming array and past start dates in the past array.
- `partitionEngagements` treats today's date as upcoming (start date == today is included in upcoming).
- `sortUpcoming` returns engagements sorted ascending by start date.
- `sortPastByYear` returns year groups sorted descending, with engagements within each group sorted descending by start date.
- Engagements with identical start dates maintain stable order based on source-list position.

### Component Tests — engagement item and accordion (co-located or in a dedicated test file)

- `EngagementItem` renders name, sessionName, location, and start date.
- `EngagementItem` renders end date when present, omits it when absent.
- `EngagementItem` renders slides link when present, omits it when absent.
- `EngagementItem` renders recording link when present, omits it when absent.
- `YearGroupAccordion` renders year trigger with `aria-expanded="false"` on initial load.
- `YearGroupAccordion` toggles `aria-expanded` to `"true"` on activation.
- `YearGroupAccordion` content panel is hidden when collapsed and visible when expanded.
- Multiple year groups toggle independently.

### E2E Tests — `src/app/tests/e2e/speaking.spec.ts`

- `/speaking` route loads without errors.
- Page displays an `<h1>` heading for the speaking page.
- Upcoming section heading is present.

- Clicking a year group trigger expands its content.
- Clicking an expanded trigger collapses the content.
