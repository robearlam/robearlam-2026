## Technical Approach

Implement a file-driven blog feature with a clear separation between data access, route composition, and presentational components.

Use `src/lib/blog/` as the data layer for loading Markdown files from `src/data/blogs/{year}/{slug}.md`, validating required frontmatter, normalizing post metadata, sorting by publish date descending, filtering by tag, and returning paginated slices. Use maintained libraries for frontmatter and Markdown processing rather than handwritten parsing logic.

Use App Router routes under `src/app/blog/` and `src/app/api/blog/` to deliver:

- SSG initial blog and tag pages with first 5 posts
- API pagination via `limit`, `offset`, and optional `tag`
- Blog detail rendering by slug with not-found fallback

Place reusable feature UI in `src/components/blog/` for feed items, list/feed container behavior, state messaging (loading/empty/end), tag links, and share links. Keep route files focused on data wiring and composition.

This approach keeps scope constrained to T003 requirements, preserves current architecture, and avoids introducing `src/features/blog/`.

## Implementation Steps

1. Define blog domain types and frontmatter schema in `src/lib/blog/`, including required fields and optional hero image.
2. Implement file discovery and Markdown/frontmatter loading from `src/data/blogs/` with deterministic descending publish-date sorting.
3. Implement reusable query helpers for slug lookup, tag filtering, and `limit`/`offset` pagination slices.
4. Add at least 15 valid Markdown sample posts across year folders with varied Markdown/HTML content and mixed tags.
5. Implement `src/app/api/blog/route.ts` to parse query params and return paginated responses using data-layer query helpers.
6. Build reusable blog listing components in `src/components/blog/` for post summary cards, tag links, and feed state messaging.
7. Implement `/blog` SSG page with first 5 posts and client continuation via API.
8. Implement `/blog/tag/[tag]` with the same pagination contract and explicit empty-state handling.
9. Build detail route `/blog/[slug]` for metadata + Markdown rendering + share action links, and return not-found for unknown slugs.
10. Add/update unit, integration, and e2e tests aligned to acceptance criteria, then run lint/typecheck/test suite and resolve failures.

## Test Plan

- Unit tests for `src/lib/blog/`:
  - frontmatter validation rejects missing required fields
  - publishDate sorting is descending and deterministic
  - tag filtering matches exact tag slug inclusion
  - pagination utility returns correct slices for varied offsets and limits
  - slug lookup returns found post or null-equivalent for missing slug
- Integration tests for route-level behavior:
  - `/blog` initial render includes latest 5 posts
  - `/blog/tag/[tag]` renders filtered set and empty state when no posts match
  - `/blog/[slug]` renders expected metadata and content for valid slug
  - `/blog/[slug]` produces 404 behavior for invalid slug
  - API route returns expected data shape/order for unfiltered and tag-filtered queries
- E2E tests for key user journeys:
  - infinite scroll loads additional posts in sequence
  - tag navigation from detail page lands on matching tag listing
  - share links exist for Facebook, LinkedIn, Reddit, X, and Bluesky and target new tabs
