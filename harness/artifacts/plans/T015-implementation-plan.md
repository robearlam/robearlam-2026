## Technical Approach

The project is on **Tailwind CSS v4**. The dark mode variant is already declared as `@custom-variant dark (&:is(.dark *))` in `globals.css`, and the `.dark` CSS custom property block is already present. There is no `tailwind.config.js` to modify.

The implementation strategy is:

1. **FOUC prevention via inline script**: Add a `<script>` element as the first child of `<body>` in `src/app/layout.tsx`. The script reads `localStorage` and `window.matchMedia('(prefers-color-scheme: dark)')`, then applies or removes the `dark` class on `document.documentElement` synchronously before the page renders. Add `suppressHydrationWarning` to the `<html>` element to prevent React hydration warnings caused by the class being present before hydration.

2. **`ThemeToggle` client component**: Create `src/components/theme-toggle.tsx` as a `"use client"` component. It reads the current theme from its own state (initialised after mount from the existing `dark` class on `documentElement`), renders the appropriate inline SVG icon (moon when light, sun when dark), toggles the class and updates `localStorage` on click, and exposes a dynamic `aria-label`.

3. **Integration into `SiteNav`**: Since `SiteNav` is already a `"use client"` component, `ThemeToggle` is imported and rendered there. On desktop it sits at the trailing end of the nav link list. On mobile it sits at the trailing end of the collapsed header bar (alongside the hamburger button), ensuring it is accessible without opening the menu.

4. **Fix hardcoded colours**: Replace `bg-white` with `bg-background` in `site-shell.tsx` and `site-nav.tsx`. Add `dark:` variants to the hardcoded hex values in `top-tags-panel.tsx`. All other components already use semantic token classes that switch automatically.

5. **Design system update**: Update `harness/design-system/design-system.md` to document the dark mode colour palette from `globals.css`.

## Implementation Steps

2. **Update `src/app/layout.tsx`**:

   - `aria-label` is dynamic: `"Switch to dark mode"` or `"Switch to light mode"` based on current state
   - Apply padding to ensure 44×44px minimum tap target
   - Ensure focus ring styling is consistent with existing nav link focus pattern

6. **Update `src/components/site-nav.tsx`**: Replace `bg-white` with `bg-background` on the mobile dropdown `<ul>` (same file as step 4)

## Risks

- **Hydration warning if `suppressHydrationWarning` is omitted**: The inline script sets a class on `<html>` before React hydrates. Without `suppressHydrationWarning` on `<html>`, React will log a warning when the server-rendered HTML (no `dark` class) differs from the client-rendered state. Must be added.
- **`useEffect` mount pattern for toggle state**: Reading `document.documentElement.classList` must happen inside `useEffect` to avoid SSR errors. A brief flash of the default (light) icon is acceptable on the very first render before hydration; this is a known pattern and is distinct from the theme-colour FOUC, which is prevented by the inline script.
- **`top-tags-panel.tsx` dark variants**: The hardcoded hex values use specific colours for active/inactive tag states. The dark variants must be chosen to maintain sufficient contrast on the dark card background (`#2a1e1e` / `var(--card)`). The build agent should choose tokens consistent with the existing `.dark` CSS variables (e.g. `var(--primary)`, `var(--muted)`) rather than introducing new hardcoded hex values.
- **Scope of `bg-white` usage**: Inspection identified two `bg-white` instances. It is possible that other components not inspected also use `bg-white`. The build agent should run a project-wide search for `bg-white` before finalising Slice 4.

## Assumptions

- The `dark` class on `document.documentElement` is sufficient to activate the `@custom-variant dark (&:is(.dark *))` Tailwind v4 variant across all components — confirmed by the variant definition `(&:is(.dark *))` which matches any element that is a descendant of an element with class `dark`
- The existing `.dark` CSS custom property block in `globals.css` represents the intended dark mode palette and should be used as-is; the design note palette is used as a reference but the CSS variables take precedence since they already express the warm brand-aligned dark theme
- The localStorage key `'theme'` with values `'dark'` or `'light'` is the canonical persistence contract
- The project does not currently use `suppressHydrationWarning` on `<html>`, so it must be added safely without side effects
- Inline SVG icons for sun and moon are acceptable and consistent with the project's existing icon approach (confirmed from `site-nav.tsx`)
- All pages are rendered within `SiteShell`, which wraps children in a `bg-background` container — so page backgrounds will switch automatically once `bg-white` hardcoding is removed from the header
