## Technical Approach

This task adds two new Next.js App Router route handlers — an RSS 2.0 feed and a WebFinger endpoint — and validates two existing crawler endpoints.

**RSS feed (`/rss`):** A route handler at `src/app/rss/route.ts` that calls `getAllBlogPosts()`, maps posts into RSS 2.0 `<item>` elements using template literals, and returns an XML response with the correct `application/rss+xml` content type. A small `escapeXml` helper handles the five XML special characters (`&`, `<`, `>`, `"`, `'`) in post titles and abstracts. Channel metadata is sourced entirely from the existing SEO constants (`SITE_NAME`, `SITE_URL`, `SITE_DESCRIPTION`), and item URLs use `canonicalUrl()`. No XML library is needed — the document shape is fixed and simple.

**WebFinger (`/.well-known/webfinger`):** A route handler at `src/app/.well-known/webfinger/route.ts` that returns a static JSON payload with `application/jrd+json` content type. The payload replicates the currently live identity mapping for `acct:RobEarlam@mastodon.social`. Query parameters are ignored — the site hosts a single identity. Next.js App Router supports dot-prefixed directory names natively.

**Robots & sitemap:** The existing `src/app/robots.ts` and `src/app/sitemap.ts` are validated in place. No code changes are required — both implementations are correct as confirmed during the design stage.

**No new dependencies** are introduced. The RSS XML is generated via template literals; no XML library is needed for this fixed-structure document.

## Implementation Steps

### Slice 1 — RSS Feed Route Handler

1. Create `src/app/rss/route.ts`.
2. Implement an `escapeXml` function that replaces `&`, `<`, `>`, `"`, `'` with their XML entity equivalents.
3. Implement a named `GET` export that:
   - Calls `getAllBlogPosts()` to retrieve all published posts (already sorted newest-first).
   - Builds channel metadata from `SITE_NAME`, `SITE_URL`, `SITE_DESCRIPTION`.
   - Maps each `BlogPostSummary` into an RSS `<item>` with title, link (via `canonicalUrl`), description, pubDate (RFC 822 via `toUTCString()`), and guid.
   - Wraps items in an RSS 2.0 channel/document structure using template literals.
   - Returns a `Response` with the XML body and `Content-Type: application/rss+xml; charset=utf-8`.

### Slice 2 — RSS Feed Tests

4. Create `src/app/tests/unit/rss-feed.test.ts`.
5. Mock `getAllBlogPosts` to return a controlled set of test posts (including one with XML-special characters in the title/abstract).
6. Write tests that invoke the `GET` handler and assert:
   - Response Content-Type is `application/rss+xml; charset=utf-8`.
   - Response body contains `<rss version="2.0">` and `<channel>`.
   - Channel metadata (`<title>`, `<link>`, `<description>`, `<language>`) is present and correct.
   - Each item contains `<title>`, `<link>`, `<description>`, `<pubDate>`, `<guid>` elements.
   - Item links and guids use the canonical `SITE_URL`.
   - XML special characters in titles/abstracts are properly escaped.
7. Run `pnpm test` to confirm tests pass.

### Slice 3 — WebFinger Route Handler

8. Create directory `src/app/.well-known/webfinger/`.
9. Create `src/app/.well-known/webfinger/route.ts`.

### Slice 4 — WebFinger Tests

## Risks

- **Dot-prefixed directory routing:** Next.js App Router supports `.well-known` directory routing, but this should be verified during build. If it doesn't work, a `rewrites` entry in `next.config.ts` would be needed as a fallback.
- **`getAllBlogPosts` I/O in tests:** The RSS test must mock `getAllBlogPosts` to avoid filesystem dependency. The mock must match the `BlogPostSummary` shape.
- **Content-Type override:** Next.js may inject or modify response headers. Tests must verify the final Content-Type values to catch any framework interference.
