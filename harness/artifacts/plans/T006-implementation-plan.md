## Technical Approach

Implement Disqus as a small blog-detail-page extension that consumes existing post metadata rather than introducing a parallel content path. The simplest sound approach is to keep the blog post route as the source of truth for per-post data, add a focused comments section beneath the rendered article content, and isolate the third-party embed in a dedicated client component because Disqus loading depends on browser-side script execution.

Site-level configuration should stay minimal and explicit. The canonical Disqus shortname is `robearlam`, and the implementation should centralize that contract in one maintainable location so the embed setup remains easy to audit and does not spread hard-coded third-party configuration across multiple files. The per-post identifier must come directly from the existing `disqusId` field already returned through the blog post metadata flow.

The implementation should preserve static generation for blog pages by keeping post lookup and page rendering on the server, while limiting client-side behavior to the embed boundary. If a post lacks a usable `disqusId`, the page should continue rendering normally and avoid breaking the article experience.

## Implementation Steps

1. Confirm the current blog post loader exposes `disqusId` to the blog detail page and tighten the metadata typing only if needed so the identifier is part of the existing post data contract.
2. Define a single maintainable Disqus configuration source using the required shortname `robearlam`, keeping the contract narrow and local to the blog comments integration.
3. Add a dedicated comments section component for blog posts that handles the client-side Disqus embed lifecycle and accepts the post identifier and page metadata as inputs.
4. Integrate that comments section into the blog detail page beneath the post body content, preserving existing article rendering, share links, and overall page structure.
5. Ensure the integration is bounded to `/blog/[slug]` only and does not introduce comment UI on blog listing or tag pages.
6. Add or update tests to cover blog-detail rendering of the comments section, correct use of `disqusId`, and non-rendering on out-of-scope blog routes.

## Risks

- The existing blog post metadata flow may not currently expose `disqusId` at the page boundary, requiring a small schema or mapping adjustment.
- Third-party embed code must run on the client, so the boundary between server-rendered article content and client-rendered comments needs to stay narrow to avoid unnecessary client expansion.
- If any posts have missing or incorrect `disqusId` values, the page can render while comments may map to the wrong thread or no thread.
- Disqus script behavior may be difficult to validate end-to-end in automated tests without relying on the live external service.

- The project's current testing setup can support route-level assertions for blog pages and, if needed, lightweight component assertions for the embed wrapper.
- Using the fixed site shortname `robearlam` satisfies the deployment contract for this task without requiring broader admin-side setup changes in the repository.
