## Title

Homepage v1

---

## Feature Goal

Deliver a production-ready homepage that replaces the placeholder page with a strong hero and curated latest content sections, using server-rendered build-time data and preserving existing component and data-layer contracts.

---

## User Value

Visitors immediately understand who the site is for and can quickly discover the newest writing, videos, and upcoming speaking activity from one clear entry point.

---

## In Scope

List the behaviours and capabilities included in this feature.

- Replace the current homepage implementation with a new layout in this order: Hero, Latest Blogs, Latest Videos, conditional Upcoming Speaking.
- Render hero content with author name as the homepage `<h1>`, intro text, and profile image from `/img/rob.png` in a responsive layout (stacked mobile, side-by-side desktop).
- Use Next.js `<Image>` for the profile image with meaningful alt text, explicit width and height, and `priority` enabled.
- Keep homepage as a server component and source data at build time through existing data-layer modules for blogs, videos, and speaking.
- Show 3 most recent blog posts sorted by `publishDate` descending, including title, publish date, and abstract, reusing existing blog card component(s) where compatible.
- Show 3 most recent videos including thumbnail, title, and publish date, reusing existing video card component(s) where compatible.
- Render Upcoming Speaking only when at least one upcoming event exists, where upcoming is defined as start date on or after the build date.
- Show all upcoming speaking events (no cap) with event name, session name, location, and start date.
- Include descriptive section headings (`<h2>`) and descriptive CTA links to `/blog`, `/videos`, and `/speaking` in applicable sections.
- Place homepage-specific presentational components under `src/components/homepage/`.
- Implement visual hierarchy and section separation consistent with existing typography-led design-system direction using Tailwind CSS only.

---

## Out of Scope

Explicitly list what this feature does NOT include.

This prevents scope creep.

- Any client-side fetching, live refresh, personalization, or runtime filtering on the homepage.
- Changes to non-homepage routes (`/blog`, `/videos`, `/speaking`, `/contact`) beyond linking.
- New CMS/content authoring workflows or new data-source schemas.
- Net-new cross-site design-system overhaul or unrelated component refactors.
- Introduction of inline styles, non-Tailwind styling systems, or TypeScript `any`-based shortcuts.

## Acceptance Criteria

Define the conditions that must be satisfied for the feature to be considered complete.

Acceptance criteria should be:

- specific
- observable
- bounded
- testable

Prefer verifiable outcomes over subjective wording.

1. `src/app/page.tsx` renders a homepage server component without a `"use client"` directive.
2. The top section contains exactly one page-level `<h1>` with text `Rob Earlam`.
3. The hero displays intro text and the profile image sourced from `/img/rob.png` via Next.js `<Image>` with non-empty alt text, explicit width, explicit height, and `priority`.
4. On small viewports, hero text and image are vertically stacked; on desktop viewports, they are side-by-side.
5. The latest blogs section renders with an `<h2>` heading and exactly 3 items, chosen by descending `publishDate` from the existing blog data layer.
6. Each rendered blog item exposes, at minimum, title, publish date, and abstract.
7. The latest blogs section includes a descriptive link to `/blog` (for example, `View all posts`).
8. The latest videos section renders with an `<h2>` heading and exactly 3 most recent items from the existing videos data layer.
9. Each rendered video item exposes, at minimum, thumbnail, title, and publish date.
10. The latest videos section includes a descriptive link to `/videos` (for example, `View all videos`).
11. Speaking data is evaluated at build time, and only events with start date on or after the build date are treated as upcoming.
12. If upcoming speaking events exist, an `<h2>` Upcoming Speaking section is rendered and contains all upcoming items with event name, session name, location, and start date, plus a descriptive `/speaking` link.
13. If no upcoming speaking events exist, no speaking section heading, list, or empty-state container is rendered.
14. Section order is fixed top-to-bottom: Hero, Latest Blogs, Latest Videos, conditional Upcoming Speaking.
15. Homepage-specific component files used for this feature are located under `src/components/homepage/`.
16. No new direct data-fetching implementation bypasses existing `src/lib/blog/`, `src/lib/videos/`, or `src/lib/speaking/` access points.
17. Styling uses Tailwind utility classes and does not introduce inline style attributes.
18. Heading hierarchy is accessible: one `<h1>` in hero and `<h2>` section headings for content sections.

Examples:

- dependency on future features
