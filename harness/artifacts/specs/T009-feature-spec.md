## Title

Videos Listing Page

---

## Feature Goal

Create a `/videos` page that presents file-backed YouTube video entries in a clear editorial listing, highlighting the newest video first and showing the remaining videos in a responsive collection below.

---

## User Value

This feature gives visitors a single place to browse published video content in a consistent, easy-to-scan format, while allowing maintainers to add new videos through Markdown content files without needing route or component registration changes.

---

## In Scope

- A new route is available at `/videos`.
- The page loads video content from Markdown files stored under `src/data/videos/YEAR/*.md`, where `YEAR` is a four-digit year folder.
- Video entries are discovered automatically across all year folders without manual registration.
- The page combines all discovered videos into one collection and sorts them by `date` descending before rendering.
- The newest video is rendered as a featured item at the top of the page.
- Remaining videos are rendered below the featured item in a responsive grid.
- Each rendered video entry includes an embedded YouTube player, the video title, and a human-readable publication date.
- If exactly one video exists, only the featured section is shown and no empty grid section is rendered.
- If no videos exist, the page renders a clear empty state message.
- The required front matter fields are `title`, `videoId`, and `date`.
- Markdown body content is optional and not required for the listing page to function.
- The specification defines predictable handling expectations for malformed or incomplete content data.
- The page should follow the v0 reference as styling guidance for visual hierarchy while remaining aligned with the existing project design system.
- Acceptance criteria include accessibility expectations for iframe titles, readable content, and keyboard-consistent behavior.

---

## Out of Scope

- Individual video detail pages.
- Video categories, filtering, search, or tagging.
- Pagination, infinite scroll, or archive segmentation.
- Runtime fetching from the YouTube API or any other external service.
- Automatic enrichment of metadata from YouTube.
- Video playback analytics, tracking, or engagement instrumentation.
- CMS-style editing workflows beyond adding Markdown files to the expected directory structure.

---

## Acceptance Criteria

- A page is available at `/videos` and presents video content as a listing page rather than redirecting or requiring dynamic route parameters.
- The page loads video entries from Markdown files located under `src/data/videos/YEAR/*.md` across all available year folders.
- Each video source file is considered valid for listing only when it includes `title`, `videoId`, and `date` in front matter.
- The `date` field is defined in `YYYY-MM-DD` format and is used for sorting all videos in descending order so the newest item appears first.
- The first item in the sorted collection is rendered in a featured treatment that is visually larger than the non-featured items rendered below it.
- All remaining items after the featured video are rendered in a responsive grid layout below the featured section.
- Each rendered video item displays its title and a human-readable publication date.
- Each rendered video item includes a YouTube embed generated from `videoId`.
- Each embedded iframe includes a meaningful `title` attribute derived from the corresponding video title.
- If the collection contains exactly one valid video, the page renders the featured video only and does not render an empty secondary grid container.
- If no valid videos are available, the page renders a clear, accessible empty state message.
- New Markdown files added under the required year-folder structure are included automatically on the page without code changes or manual registration.
- Markdown body content may be absent without preventing the video from rendering on the listing page.
- Malformed or incomplete video files are handled predictably: they must not cause the entire `/videos` page to fail to render, and the chosen handling behavior must be consistent across all video entries.
- The visual hierarchy of one featured video followed by smaller supporting video cards matches the intent of the provided v0 reference while staying consistent with the project’s established design system.
- The page remains readable and usable on mobile and desktop viewport widths, with the featured section and supporting grid adapting without overlapping or orphaned empty sections.
- Keyboard navigation and focus behavior for links and interactive elements on the page remain consistent with the rest of the site.
- The feature is specified so it can be validated through route-level review and UI-focused tests that verify visible behavior rather than implementation details.

## Dependencies

- Markdown video content files must exist under `src/data/videos/YEAR/*.md` for the populated page state to be exercised.
- A consistent front matter schema is required for `title`, `videoId`, and `date`.
- The implementation stage will depend on existing or newly introduced content-loading utilities that can discover and parse Markdown files.
- The implementation stage will depend on project-aligned UI components or layouts that can express the featured-plus-grid editorial hierarchy.
- The v0 output referenced in the task is a dependency for design intent only, not as a source of production code requirements.

## Risks

- Content authors may introduce malformed dates or omit required front matter, which could lead to inconsistent ordering or missing entries if handling rules are not explicit.
- The v0 reference may not map cleanly onto existing site patterns, creating ambiguity about how closely visual treatment should be matched.
- Empty-state and partial-content behavior may be overlooked if only populated examples are considered during implementation.
- If malformed content handling is not implemented consistently, maintainers may have difficulty understanding why a video is missing from the page.
