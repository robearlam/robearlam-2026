## Title

Videos Page — Infinite Scroll Paging

---

## Feature Goal

Introduce infinite scroll paging on the `/videos` route so that the existing editorial hierarchy (featured video + grid) is preserved on initial load, while additional non-featured video cards are progressively loaded in fixed-size batches as the user scrolls toward the end of the list.

---

## User Value

The `/videos` page currently renders all video cards at once. As the video library grows, this creates unnecessary upfront data loading and degrades page performance. Infinite scroll allows the page to load quickly with the most important content visible first, then fetch additional content on demand — reducing initial payload and keeping the page responsive. The interaction pattern mirrors the existing blogs page, giving returning visitors a consistent experience across content sections.

---

## In Scope

- The featured video (newest video, rendered as a large hero card) is always shown on initial server-side render with no change to its visual treatment or ordering logic.
- On initial page load, exactly 6 non-featured videos are rendered beneath the featured video (2 rows of 3 cards).
- When the user scrolls to the bottom of the rendered video list, additional non-featured videos are automatically loaded in batches of 6 (2 rows of 3 cards).
- Batching continues until all non-featured videos have been loaded; no further network requests are triggered once the full list is displayed.
- A final batch that contains fewer than 6 videos renders without layout breakage (no empty card placeholders or broken grid).
- A Next.js API route at `/api/videos` is created, accepting `limit` and `offset` query parameters, returning only non-featured paginated video data.
- A `getPaginatedVideos()` function is created in `src/lib/videos/` for use by both the API route and the server-side initial render.
- A client component (`VideosGridClient` or equivalent) is created with `"use client"`, fetching additional batches via `fetch('/api/videos?limit=…&offset=…')` on infinite-scroll trigger events.
- The `/videos` page server component calls `getPaginatedVideos()` directly for the first batch (SSR), passing `initialVideos` and `initialHasMore` to the client component as props.
- Infinite-scroll trigger, loading-state handling, and end-of-list behavior follow the same UX pattern as the existing blogs listing page.
- Existing intersection observer, hook, or utility code from the blog feature is reused where applicable.
- Video ordering remains date-descending (newest first) throughout all initial and subsequent batches.
- Responsive layout (mobile / tablet / desktop) is maintained across the full paginated list.
- Any intentional behavioral difference from the blog infinite-scroll pattern is documented in this specification.

**Intentional Differences from Blog Infinite Scroll**

- The featured video is a first-class element unique to the videos page; it is always rendered outside the paged grid and is never included in the `offset`-based pagination query. The API route and `getPaginatedVideos()` must exclude the featured video from all paginated results.
- There is no equivalent "featured post" concept on the blogs page, so the exclusion logic has no direct parallel in the blog implementation.

## Acceptance Criteria

**Initial Render**

1. On route `/videos`, the newest video is rendered as the single featured large video at the top of the page.
2. On initial page load, exactly 6 non-featured video cards are visible beneath the featured video, arranged in 2 rows of 3.
3. No more than 6 non-featured video cards are rendered before any scroll action has occurred.
4. The featured video is not duplicated in the non-featured grid.

**Infinite Scroll Loading**

5. When the user scrolls to the bottom of the rendered video list (and more videos remain), an additional batch of up to 6 non-featured videos is appended to the grid automatically.
6. Each subsequent load event appends exactly 6 non-featured videos until fewer than 6 remain.
7. A final batch containing fewer than 6 non-featured videos is appended without producing empty card slots or breaking the 3-column grid layout.
8. Once all non-featured videos are displayed, no further requests to `/api/videos` are triggered on subsequent scroll events.

**API Route**

9. A GET request to `/api/videos?limit=6&offset=0` returns the first 6 non-featured videos in date-descending order as a JSON response.
10. A GET request to `/api/videos?limit=6&offset=6` returns the next 6 non-featured videos (if available).
11. The response includes enough metadata for the client to determine whether further batches are available (e.g., a `hasMore` or total count field).
12. The featured video (first in date-descending sort) is never returned by the `/api/videos` route.

**Layout & Visual Consistency**

13. Non-featured video cards rendered via infinite scroll are visually consistent (same card component, spacing, alignment) with the initial server-rendered cards.
14. The 3-column grid layout is maintained at desktop breakpoints for all appended batches.
15. Responsive layout behaves correctly at mobile and tablet breakpoints for all appended batches.

**Behavior Parity with Blogs**

16. The infinite-scroll trigger fires based on the same intersection observer pattern used by the blogs listing page.
17. A visible loading indicator (if present in the blog pattern) is shown during a fetch and hidden once the batch is appended.
18. End-of-list state (if communicated visually or accessibly in the blog pattern) is reflected identically once all videos are loaded.

**Accessibility & UX**

19. Any loading indicator introduced is announced appropriately for screen readers (e.g., via `aria-live` or equivalent).
20. Keyboard focus behavior is not disrupted when new cards are appended to the DOM.
21. Rapid or repeated scroll events do not cause duplicate append operations (race condition protection).

**Edge Cases**

22. If the video data source contains zero videos, the existing empty state is preserved unchanged.
23. If the video data source contains exactly 1 video (the featured video only), no non-featured grid is rendered and no infinite-scroll behavior is triggered.
24. If the video data source contains between 1 and 6 non-featured videos, all non-featured videos are rendered on initial load and no further paging requests are triggered.
25. If the video data source contains more than 6 non-featured videos, the first batch renders 6 on initial load and additional batches load on scroll.

## Risks

- If the blog infinite-scroll pattern uses tightly coupled implementations that are not easily reused, additional abstraction work may be needed — this should be flagged during implementation planning rather than creating new parallel abstractions speculatively.
- If the number of videos in the data source is very small (≤ 7, meaning ≤ 6 non-featured), the infinite-scroll behavior will not be exercisable in development, making manual testing dependent on adding test data.
- Intersection observer behavior can differ across browsers; the blog pattern's existing cross-browser handling should be inherited, not reimplemented.
- Rapid scroll events triggering duplicate fetches must be guarded against; the blog pattern's debounce or in-flight guard should be replicated exactly.
