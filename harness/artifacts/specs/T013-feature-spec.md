## Title

Blog Hero Images

---

## Feature Goal

Extend blog discovery surfaces so homepage preview cards and blog listing cards display each post's hero image when available, with a consistent fallback image when it is not.

---

## User Value

Users browsing the homepage or blog listings can identify and evaluate posts more quickly because blog cards include a visual preview that reflects the post content while preserving the current navigation and metadata cues.

---

## In Scope

List the behaviours and capabilities included in this feature.

- Add image rendering to each card in the homepage "Latest Blogs" preview section.
- Add thumbnail rendering to each post card across all blog listing pages included in the current listing experience.
- Use a post's existing optional `heroImage` value when one is defined.
- Use the existing placeholder asset at `/src/public/img/blog-images/blog-placeholder.png` when a post does not define a hero image.
- Ensure card images link to the same post destination as the associated title or card.
- Preserve current latest-post selection, reverse-chronological ordering, pagination, archive filtering, tag filtering, and existing text metadata.
- Define acceptance criteria for responsive presentation, intentional fallback behavior, meaningful alt text, and avoidance of obvious layout breakage or severe image-load shift.

---

## Out of Scope

Explicitly list what this feature does NOT include.

This prevents scope creep.

- Changing the markdown schema or introducing a new image metadata field.
- Changing individual blog post detail page hero-image behavior beyond any strictly necessary supporting alignment identified during implementation.
- Redesigning homepage or blog listing information architecture, content strategy, or card copy.
- Replacing the existing latest-post selection logic or altering current listing/filtering rules.
- Introducing new image-management workflows, editorial tooling, or additional placeholder assets.

## Acceptance Criteria

Define the conditions that must be satisfied for the feature to be considered complete.

Acceptance criteria should be:

- specific
- observable
- bounded
- testable

Prefer verifiable outcomes over subjective wording.

Stronger examples:

- A shared root layout wraps all pages under the main app route tree.
- Header navigation is visible on all pages using the shared layout.
- The layout uses the standard centered content container defined by the design system.

Avoid vague examples such as:

- The layout feels polished.
- The spacing looks good.
- The page feels consistent.

1. The homepage "Latest Blogs" section renders one image per preview card for the same three posts selected by the existing latest-post behavior.
2. When a homepage previewed post defines a hero image, that image is shown on its preview card.
3. When a homepage previewed post does not define a hero image, its preview card shows the existing placeholder asset at `/src/public/img/blog-images/blog-placeholder.png` instead of an empty, broken, or missing image state.
4. Each homepage preview card image links to the same blog post destination as the card title.
5. Homepage preview cards continue to display the existing publish date, title, abstract, and tags correctly after image support is added.
6. All blog listing pages in the current blog browsing experience render one thumbnail image for each listed post card.
7. When a listed post defines a hero image, that image is used as the listing thumbnail for that post.
8. When a listed post does not define a hero image, the listing thumbnail uses the existing placeholder asset at `/src/public/img/blog-images/blog-placeholder.png`.
9. Each listing thumbnail links to the same blog post destination as the associated title or card.
10. Existing listing behavior remains intact after thumbnail support is added, including current ordering, pagination, archive filtering, and tag filtering where applicable.
11. Existing listing metadata remains present and correct after thumbnail support is added.
12. Homepage and blog listing card layouts remain functional and readable on mobile and desktop without image-driven overlap, clipping that obscures core content, or broken card structure.
13. Card images expose meaningful alt text behavior that preserves or improves current accessibility quality for both hero-image and placeholder cases.
14. Image rendering on homepage and blog listing cards avoids obvious layout breakage and severe cumulative layout shift during load.
15. The feature reuses the existing blog data model as the source of truth for optional hero-image data and does not introduce duplicate image metadata.
16. Focused automated coverage is added where practical for fallback behavior when a post has no hero image.
17. The implementation passes lint, typecheck, and relevant automated tests without regressing existing homepage or blog listing behavior.
