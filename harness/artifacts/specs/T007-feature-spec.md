## Title

Blog Sidebar Panels — Top Tags and Monthly Archive

---

## Feature Goal

Add a persistent right-column sidebar to the blog listing page and tag listing pages. The sidebar contains two panels: a Top Tags panel listing the ten most-used tags, and a Monthly Archive panel listing all months that contain at least one post. A new archive route is introduced to display posts filtered by year and month.

---

## User Value

Readers browsing the blog gain two discovery mechanisms without leaving the current page. The Top Tags panel lets them jump directly to a topic of interest. The Monthly Archive panel lets them browse posts by time period. Both panels reduce friction for content discovery and increase the depth of engagement with the blog.

---

## In Scope

- A shared sidebar component rendered on the blog listing page (`/blog`) and all tag listing pages (`/blog/tag/[tag]`)
- A **Top Tags** panel within the sidebar listing the top 10 tags across all blog posts, each rendered as a link to `/blog/tag/[tag]`
- Visual highlighting of the active tag in the Top Tags panel when the user is on a tag listing page
- A **Monthly Archive** panel within the sidebar listing all months and years that contain at least one post, each rendered as a link to `/blog/[year]/[month]` (zero-padded month, e.g. `03`)
- Human-readable month/year labels in the Monthly Archive panel including a post count in parentheses (e.g. "March 2026 (4)")
- Per-month post count aggregation in the data layer to support the count display in the Monthly Archive panel
- The archive route `/blog/[year]/[month]` displaying only posts published in that month and year
- The archive listing page following the same visual layout and pagination pattern as the tag listing page
- An appropriate empty-state message on the archive page when a valid URL has no matching posts, consistent with the tag page empty state
- The Top Tags panel rendered above the Monthly Archive panel in the sidebar
- The sidebar hidden on small screens and visible only from the `md` Tailwind breakpoint upward
- Static generation (`generateStaticParams`) for the archive route, consistent with the tag route implementation
- Extension of existing data functions (e.g. `getPaginatedBlogPosts`) to support month/year filtering rather than duplicating data-access logic
- Both panels styled in accordance with the existing design system: restrained palette, editorial tone, border/card treatment consistent with the site

---

## Out of Scope

- Post counts in the Top Tags panel (tags are shown as labels only)
- Pagination of the Top Tags panel (always shows exactly the top 10)
- Blog post detail pages
- Disqus integration
- Any changes to the site header, footer, or navigation
- Search or filtering beyond tag and month/year
- Sidebar visibility on blog post detail pages

---

## Acceptance Criteria

1. The blog listing page (`/blog`) renders a two-column layout with the main feed on the left and the sidebar on the right.
2. All tag listing pages (`/blog/tag/[tag]`) render the same two-column layout with the sidebar.
3. The sidebar contains a Top Tags panel that lists exactly the top 10 tags by post count.
4. Each tag in the Top Tags panel is a link that navigates to `/blog/tag/[tag]`.
5. When on a tag listing page, the tag matching the current route is visually highlighted in the Top Tags panel. No post count is displayed for any tag in the Top Tags panel.
6. The sidebar contains a Monthly Archive panel that lists every month and year combination that has at least one post.
7. Each entry in the Monthly Archive panel is a link that navigates to `/blog/[year]/[month]` using a zero-padded two-digit month.
8. Monthly Archive entries display a human-readable label followed by the post count for that month in parentheses (e.g. "March 2026 (4)").
9. No months are hidden or truncated in the Monthly Archive panel.
10. The Top Tags panel appears above the Monthly Archive panel in the sidebar.
11. The sidebar is not visible on small screens and becomes visible at the `md` Tailwind breakpoint.
12. The archive route `/blog/[year]/[month]` exists and renders only posts published in that month and year.
13. The archive listing page uses the same visual layout and pagination pattern as the tag listing page.
14. Navigating to a valid archive URL that has no matching posts renders an empty-state message consistent with the tag page empty state.
15. Both sidebar panels use styling consistent with the existing design system (editorial palette, border/card treatment).

---

## Dependencies

- Existing blog data functions (`getPaginatedBlogPosts` and related utilities in `src/lib/blog/`) must support month/year filtering and must return per-month post counts for the archive panel
- The tag listing page component must be refactored or wrapped to accept a shared sidebar component without duplicating layout logic
- Blog post frontmatter must include a parseable publication date for month/year grouping
- The design system's grid, card, and typography tokens must be available for sidebar styling

---

## Risks

- If blog post dates are inconsistently formatted across markdown files, the month/year grouping logic may produce incorrect results — this should be validated early during implementation
- If the tag listing page layout is tightly coupled to its current single-column structure, introducing the sidebar may require layout refactoring that increases implementation complexity
- Static generation of the archive route depends on all valid year/month combinations being known at build time; runtime-only posts would not be covered without ISR or fallback handling
- Deriving per-month post counts alongside filtering may require a second data pass or an aggregate query; this should be validated during implementation planning to avoid unnecessary duplication
