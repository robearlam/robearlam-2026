## Title

Blog Post Disqus Comment Integration

---

## Feature Goal

Enable Disqus comments on individual blog post pages so each post automatically loads its associated discussion thread using the post's existing canonical Disqus identifier.

---

## User Value

Readers can view existing discussion on blog posts and add new comments without leaving the post page, which restores community interaction for imported posts and keeps engagement attached to the correct article.

---

## In Scope

List the behaviours and capabilities included in this feature.

- Render a Disqus embed on individual blog detail pages only.
- Load the Disqus thread automatically when a user views a blog detail page.
- Use each post's existing `disqusId` frontmatter value as the canonical per-post Disqus identifier.
- Use the site Disqus shortname `robearlam` as the site-level Disqus configuration value.
- Define the required configuration contract for any site-level Disqus settings so deployment requirements are explicit and maintainable.
- Preserve the existing blog page structure and normal blog content rendering while adding comments below the post content.
- Keep metadata sourcing aligned with the existing blog architecture so the integration uses existing post metadata rather than duplicating it.

---

## Out of Scope

Explicitly list what this feature does NOT include.

This prevents scope creep.

- Adding Disqus comment embeds to blog listing pages, tag pages, or any non-post route.
- Adding comment count badges, listing-page comment previews, or any comment summary UI outside the post detail page.
- Defining Disqus moderation workflows, admin configuration steps, or account-management processes.
- Changing blog content schema beyond consuming the existing `disqusId` field.
- Redesigning the blog post layout beyond the minimum placement needed to include the comments section.

## Acceptance Criteria

Define the conditions that must be satisfied for the feature to be considered complete.

Acceptance criteria should be:

- specific
- observable
- bounded
- testable

Prefer verifiable outcomes over subjective wording.

Stronger examples:

- A shared root layout wraps all pages under the main app route tree.
- Header navigation is visible on all pages using the shared layout.
- The layout uses the standard centered content container defined by the design system.

Avoid vague examples such as:

- The layout feels polished.
- The spacing looks good.
- The page feels consistent.

- Visiting a blog detail route under `/blog/[slug]` renders a Disqus comments section beneath the post body content on that page.
- The Disqus embed is not rendered on the main blog listing page or tag listing pages.
- For a blog post that includes a `disqusId` value in frontmatter, the Disqus integration uses that exact value as the post identifier passed to Disqus.
- The Disqus site shortname used by the integration is `robearlam`.
- When Disqus is configured correctly, existing comments associated with the post's `disqusId` are displayed within the embedded comments section.
- When Disqus is configured correctly, a visitor can access the standard embedded Disqus flow to submit a new comment from the blog detail page.
- The comments integration does not prevent the blog detail page from rendering its post content and metadata during normal page load.
- The feature does not introduce duplicate post metadata definitions for Disqus configuration when sourcing blog post information.
- The required site-level configuration contract for the Disqus integration is documented clearly enough that a maintainer can determine what value must be supplied for deployment.
- The feature remains bounded to blog detail pages and does not add any additional discussion-related features beyond embedded viewing and submission of comments.

## Dependencies

Identify anything required before implementation can proceed.

Examples:

- existing components
- content requirements
- external services

- Existing blog post frontmatter must continue to provide a valid `disqusId` for each post intended to support comments.
- The Disqus service must have the site shortname `robearlam` available and configured for the deployed site.
- The current blog architecture must expose post metadata to the blog detail page so the canonical Disqus identifier can be sourced without duplicating metadata logic.
- Deployment must provide any required site-level configuration values defined by the implementation contract.

---

## Risks

Identify potential issues that could affect implementation.

Examples:

- unclear content requirements
- dependency on future features
- unknown technical constraints

- If a post is missing or has an incorrect `disqusId`, the wrong Disqus thread could render or no existing comments could appear.
- If site-level Disqus configuration is not supplied consistently across environments, the embed may fail at runtime even though the page itself still loads.
- If the integration bypasses existing blog metadata flow, the implementation could drift from the current blog architecture and become harder to maintain.
- Third-party embed behavior may introduce runtime dependencies outside the project's direct control.
