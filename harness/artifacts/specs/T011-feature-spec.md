## Title

SEO, AEO, and GEO Foundations

---

## Feature Goal

Establish site-wide SEO, AEO, and GEO foundations so all current public routes are consistently discoverable, crawlable, indexable as intended, and machine-readable for both traditional search engines and LLM-based discovery systems.

---

## User Value

Visitors can find relevant pages more reliably in search and AI-driven answer experiences, receive accurate previews when content is shared, and access pages whose metadata and content signals are consistent and trustworthy.

---

## In Scope

- Site-wide baseline metadata quality for all indexable routes, including unique page title and description.
- Canonical URL policy for indexable routes.
- Open Graph and Twitter/X card metadata coverage for key page types: home, blog post, videos, speaking, contact.
- Use of Next.js metadata APIs as the default metadata generation mechanism where practical.
- Technical SEO foundations: XML sitemap generation, robots.txt presence, and explicit index/noindex behavior.
- Internal-linking sufficiency review for crawler discovery of key content hubs.
- Structured data coverage with JSON-LD for `WebSite`, site identity (`Person` or `Organization`), `WebPage` on key routes, `BlogPosting`, `VideoObject` where applicable, and `Event` where applicable.
- AEO/GEO readiness signals: concise page summaries, clear author/entity identity, semantic heading hierarchy, citation-friendly canonical cues, and metadata/content semantic alignment.
- Crawler accessibility checks for major AI crawler policy compatibility via robots/sitemap review.
- GA4 integration for core page-view tracking across in-scope routes with duplicate page-view prevention on route transitions.
- Guardrails ensuring no accessibility-semantic regressions and no validation regressions in lint, typecheck, and existing test suites.
- Focused tests for new reusable helper utilities where practical.

---

## Out of Scope

- Net-new content strategy, copywriting overhaul, or broad editorial rewrites beyond concise summary blocks needed for AEO/GEO clarity.
- Off-site SEO work such as backlink campaigns, third-party directory submissions, or social distribution strategy.
- New analytics event taxonomy beyond GA4 baseline page-view implementation needed by this task.
- Performance optimization initiatives not directly required to satisfy SEO/AEO/GEO acceptance criteria.
- Any workflow governance file changes or lifecycle stage transitions.

---

## Acceptance Criteria

1. Baseline metadata coverage:
- Every indexable route in current scope renders a non-empty, route-unique `<title>` and `meta description`.
- Canonical URL metadata is present for every indexable route and matches the intended canonical route.
- Home, blog post, videos, speaking, and contact routes each include valid Open Graph metadata and aligned Twitter/X card metadata.
- Metadata generation for these routes is implemented through Next.js metadata APIs except where a documented framework limitation applies.

2. Technical SEO foundations:
- XML sitemap output is valid XML and includes all intended indexable routes in current scope.
- A valid robots.txt is present and explicitly reflects intended crawler access policy.
- Index/noindex behavior is explicit for in-scope routes and matches page intent.
- At least one internal crawl path exists from primary navigation or content hubs to each key route type (home, blog, videos, speaking, contact).

3. Structured data validity and coverage:
- Global structured data includes `WebSite` and exactly one site identity schema type (`Person` or `Organization`) with consistent identity naming.
- Key route types include `WebPage` schema.
- Blog post routes include `BlogPosting` schema.
- Video listing/detail contexts include `VideoObject` where content exists.
- Speaking engagement contexts include `Event` where event data exists.
- JSON-LD emitted by in-scope routes validates without critical errors in schema/rich-result validation checks.

4. AEO/GEO readiness:
- Each key route type contains a concise, visible summary block describing page intent in LLM-readable language.
- Author/entity clarity signals are present and consistent across key routes.
- Heading structure on key routes follows semantic hierarchy without skipped levels that would impair extraction.
- Canonical source cues are stable and consistent between metadata and visible page context.
- No contradiction exists between machine-readable metadata/structured data and visible user-facing content.

5. Analytics behavior:
- GA4 is integrated in a production-safe way and loads only in intended runtime environments.
- Core page-view tracking is observed across all in-scope route types.
- Route transitions do not produce duplicate page-view firing for a single navigation event.

6. Quality and regression guardrails:
- SEO/AEO/GEO changes do not remove or degrade existing accessibility semantics on in-scope routes.
- Lint, typecheck, and existing automated test suites pass after implementation.
- New helper utilities introduced for metadata/schema generation are typed and have focused unit coverage where practical under the project testing standard.

---

## Dependencies

- Existing route/content data sources for blog, videos, speaking, contact, and homepage contexts.
- Stable canonical site URL configuration used consistently by metadata, sitemap, and schema generation.
- GA4 measurement ID and environment configuration for safe runtime loading.
- Next.js metadata and routing capabilities currently available in the project stack.

---

## Risks

- Inconsistent or incomplete source content may limit schema completeness for some routes.
- Canonical URL drift between route generation and metadata generation may cause duplicate-index risk.
- Analytics duplication risk on client-side navigation if integration hooks are not centralized.
- Overly restrictive robots policy could unintentionally limit AI crawler or search crawler access.
