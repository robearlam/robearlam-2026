# Task T007.1 — Blog Sidebar Refinements

Status: Ready  
Backlog Item: B011  
Created: 2026-03-24

---

## Summary

Follow-up refinements to the blog sidebar panels delivered in T007:

1. **Year groupings in the date panel** — The Monthly Archive panel should group months under collapsible or visually distinct year headings. Each year heading displays the total number of posts for that year and is itself a clickable link navigating to a new year-level archive route (`/blog/[year]`).
2. **Wrapped tag chips in the Top Tags panel** — Tags should render as a wrapping flex row of chip-style elements rather than a vertical list, giving a more compact and visually appealing tag-cloud appearance.
3. **Wider inner content column** — The main content column in the two-column blog layout (and consistently across all pages that share the same shell/container) is currently too narrow. Expand it so content feels less squashed, maintaining visual consistency site-wide.

## Acceptance Criteria

- The Monthly Archive panel groups months under year headings
- Each year heading displays the total post count for that year (e.g. "2026 (12)")
- Each year heading is a clickable link to `/blog/archive/[year]` (e.g. `/blog/archive/2026`)
- The new year-level archive route `/blog/archive/[year]` is implemented and displays all posts published in that year, following the same layout and pagination pattern as the tag and month/year archive pages
- Static generation (`generateStaticParams`) is used for the year route, consistent with other archive routes
- Navigating to a valid year URL with no posts shows an appropriate empty state message
- Tags in the Top Tags panel render as a wrapping row of chip-style elements (flex-wrap) rather than a vertical list
- Tag chips retain their count display, link behaviour, and active-state highlight from T007
- The inner content column width is increased across all pages that share the global shell/container so content no longer appears squashed
- The layout change is visually consistent across `/blog`, `/blog/tag/[tag]`, `/blog/archive/[year]/[month]`, `/blog/archive/[year]`, and any other pages using the shared layout
- All existing T007 acceptance criteria continue to pass

---

## Task Notes

- The year route URL format is `/blog/archive/[year]` using a four-digit year (e.g. `/blog/archive/2026`)
- Year headings in the archive panel should display in descending order (most recent first); months within each year also descend
- The chip style for tags should follow the existing design system — restrained palette, small rounded pill or badge treatment, consistent with editorial style
- Width adjustment should be made at the shared layout/container level so all pages benefit; avoid per-page one-off overrides
- The existing `getPaginatedBlogPosts` filtering logic should be extended to support year-only filtering (no month specified), keeping query logic centralised
