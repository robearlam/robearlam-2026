# Task T009.1 — Videos Infinite Scroll Paging

Status: Ready  
Backlog Item: B012  
Created: 2026-03-26

---

## Summary

Introduce infinite scroll paging on `/videos` so the page keeps the existing editorial hierarchy while progressively loading additional video cards in fixed-size batches.

The initial render must include:
- The featured large video (newest video)
- 2 full rows of 3 non-featured videos (6 videos total) beneath the featured video

After initial render, infinite scroll should load additional non-featured videos in batches of 2 rows (6 videos) at a time until the end of the list is reached.

The implementation must follow the same infinite-scroll interaction pattern already used for the blog listing page, including a dedicated API route for serving paginated video data.

## Acceptance Criteria

**Initial Render & Paging Behavior**
- On route `/videos`, the newest video remains rendered as the single featured large video at the top
- On initial page load, exactly 6 non-featured videos are rendered beneath the featured video (2 rows of 3)
- Additional non-featured videos are loaded automatically via infinite scroll in fixed batches of 6 (2 rows) per load event
- Infinite scroll continues loading in 6-item batches until all remaining non-featured videos are displayed
- The final load handles a remainder batch smaller than 6 without layout breakage
- Once all non-featured videos are displayed, no further load requests are triggered

**Layout & Visual Consistency**
- The grid remains 3-up per row at desktop breakpoints (matching current `/videos` card layout intent)
- Initial and subsequent batches preserve consistent spacing, alignment, and card treatment with existing `/videos` design
- Responsive behavior remains correct across mobile/tablet/desktop breakpoints
- The featured video presentation and ordering logic are unchanged from T009

**Behavior Parity with Blogs Infinite Scroll**
- Infinite-scroll trigger behavior, loading-state handling, and end-of-list behavior follow the same UX pattern used by the blogs page
- A Next.js API route at `/api/videos` must be created to serve paginated non-featured video data, accepting `limit` and `offset` query parameters — mirroring `/api/blog`
- The client component must fetch additional batches from `/api/videos` via `fetch()` (not in-memory slicing), matching the `BlogFeedClient` async load pattern
- Implementation should reuse existing pagination/infinite-scroll utilities, hooks, or observer patterns from the blog feature where practical
- Any intentionally different behavior from blogs must be documented in the feature specification

**Data & Ordering Rules**
- Video ordering remains date-descending (newest first) from the existing video data pipeline
- Featured video is still the first item in the sorted list and excluded from paged grid batches
- Paged batches are applied only to the remaining non-featured list in stable order

**Accessibility & UX**
- Infinite scroll loading indicators (if present) are accessible and screen-reader friendly
- Keyboard and focus behavior remain predictable while new cards are appended
- End-of-list state is communicated clearly and accessibly (if a visible message exists in the pattern)

**Edge Cases**
- If there are no videos: existing empty state behavior is preserved
- If there is only one video: only featured video is shown; no infinite scroll behavior is triggered
- If there are 1-6 non-featured videos: all non-featured videos render on initial load with no additional paging
- If total remaining non-featured videos exceed 6: batches continue at +6 per load until complete

## Task Notes

**Scope Clarification**
- This task extends T009 and is focused only on incremental loading behavior for the `/videos` listing
- No changes to video content schema or source file structure are required
- No changes to individual video detail routing (if introduced later) are included

**Implementation Guidance**
- Follow the blogs infinite-scroll implementation approach exactly: API route → paginated lib function → client component with `fetch()`-based `loadMore`
- Create a `getPaginatedVideos()` function in `src/lib/videos/` analogous to `getPaginatedBlogPosts()` in `src/lib/blog/posts.ts`
- Create a Next.js API route at `src/app/api/videos/route.ts` analogous to `src/app/api/blog/route.ts`, accepting `limit` and `offset` query params
- Create a `VideosGridClient` (or equivalent) `"use client"` component analogous to `BlogFeedClient`, fetching from `/api/videos`
- The `/videos` page server component should call `getPaginatedVideos()` directly for the initial batch (SSR), then pass `initialVideos` and `initialHasMore` to the client component
- Keep the featured video outside the paged list logic to avoid accidental duplication or reorder; the API route serves only non-featured videos
- Ensure the implementation avoids duplicate append operations under rapid scroll or repeated intersection events

**Out of Scope**
- Filtering, sorting controls, and search on `/videos`
- URL/stateful pagination parameters (page query string)
- Changes to video card design beyond what is needed for stable infinite loading UX
